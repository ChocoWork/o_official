# 会計取引テンプレート再保存設計

> 対象: Admin ページ / ACCOUNTING タブ / 取引管理

---

## 概要

登録済みテンプレートを取引フォームへ適用し、一部を変更した後、その内容を同じテンプレートへ上書き、または別名の新しいテンプレートとして保存できるようにする。

誤上書きを避けるため、上書きと別名保存は明示的に分離する。別名保存で既存名が指定された場合は保存せず、重複エラーを表示する。

## 対象範囲

- 新規取引 Drawer と既存取引の編集 Drawer のテンプレート操作
- 支出テンプレートと収入テンプレート
- テンプレートの上書き保存、別名保存、重複検証
- 保存中、成功、失敗時の表示
- 単体テストおよび mobile、tablet、desktop の E2E テスト

既存のテンプレート削除、取引保存、証憑、摘要選択の仕様は変更しない。取引先はテンプレートの保存・再適用対象へ追加する。日付とシーズンは対象外とする。

## UI と操作

登録済みテンプレートを選択すると、従来の削除操作に加えて次の操作を表示する。

| 操作 | 動作 |
|------|------|
| 変更を上書き | 現在のフォーム内容を選択中のテンプレート名で保存する |
| 別名で保存 | テンプレート名入力欄を開き、新しいテンプレートとして保存する |

「変更を上書き」では、対象名を示す確認ダイアログを表示する。確定するまで更新リクエストは送信しない。

「別名で保存」では、選択中のテンプレート名を入力欄の初期値にする。利用者が名前を変更して保存する。取消時はテンプレート名入力だけを閉じ、取引 Drawer とフォーム入力は維持する。

テンプレート未選択時の「＋ 現在の入力を保存」は従来どおり新規保存として扱う。

## データフロー

上書き保存は、選択中のテンプレート名を更新対象として API へ渡し、現在のフォーム内容で更新する。対象が存在しない場合はエラーとし、暗黙に新規作成しない。

別名保存は新規作成として API へ渡す。正規化後の名前が既存テンプレート名と一致する場合は競合エラーを返し、既存内容を変更しない。画面側の事前検証に加え、同時操作を考慮して API 側でも重複を判定する。

保存対象の項目は既存仕様を維持する。

- 種別
- 勘定科目
- 摘要
- 取引先
- 金額
- 入出金方法
- メモ

## エラー処理

- 別名保存の名前が空の場合は入力を促す。
- 同名が存在する場合は「同じ名前のテンプレートが存在します。」と表示する。
- 上書き対象が削除済みなどで存在しない場合は、再選択を促す。
- API エラー時はフォーム、選択中テンプレート、入力中の別名を保持する。
- 保存中は二重送信を防止する。
- 成功後はテンプレート一覧を再取得し、保存したテンプレートを選択状態にする。

## 既存動作との整合

- 支出と収入のテンプレートは引き続き別管理とする。
- テンプレート名入力中の IME 変換確定では保存しない。
- 未保存のテンプレート名がある状態で Drawer を閉じる場合は、既存の未保存確認を維持する。
- 削除操作は上書き・別名保存とは独立させる。
- 既存の共通 `Button`、`TextField`、`Dialog`、`SingleSelect` を使用する。

## テスト方針

単体テストでは次を検証する。

- 選択したテンプレートを変更し、確認後に同名で上書きできる。
- 上書き確認を取り消すと API を呼ばず、フォームを保持する。
- 選択したテンプレートを変更し、別名で新規保存できる。
- 別名保存で既存名を指定すると保存せず、重複エラーを表示する。
- API 側が新規作成の重複を拒否し、更新では既存行だけを変更する。
- 新規保存と上書きの双方で取引先を永続化し、選択時にフォームへ再適用する。
- API エラー後も入力内容を保持する。

E2E テストでは mobile、tablet、desktop の各画面幅で両方の保存操作、確認ダイアログ、重複エラー、および横スクロールが発生しないことを検証する。

## 完了条件

- 新規取引と既存取引の編集の両方で、テンプレート適用後に上書き保存と別名保存を選べる。
- 別名保存が既存テンプレートを誤って上書きしない。
- 既存のテンプレート入力保護、支出・収入別管理、削除操作が維持される。
- 対象の単体テスト、E2E テスト、型検査、Lint、セキュリティ監査が完了する。
