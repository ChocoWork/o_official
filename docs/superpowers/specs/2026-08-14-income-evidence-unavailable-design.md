# 収入取引の証憑添付不可記録設計

## 概要

ACCOUNTING の取引管理で、手動登録した収入取引に証憑を添付できない事情を記録できるようにする。アクション名は「証憑添付不可」、記録後の状態表示は「理由記録済み」とする。

この機能は証憑の法定保存義務を免除するものではない。銀行の閲覧期限超過などにより本システムへ添付できない事実、確認した代替情報、記録日時を残し、単なる未対応の「未添付」と区別する。支出取引および注文データ由来の収入取引の挙動は変更しない。

| 証憑ファイル | 添付不可記録 | 表示状態 |
|---|---|---|
| あり | あり／なし | 添付済み |
| なし | あり | 理由記録済み |
| なし | なし | 未添付 |
| 注文データ由来 | 対象外 | 注文データ保存済み |

## 1. 対象と基本動作

- 対象は `source=manual` かつ `entryType=income` の取引に限定する。
- 新規登録時と既存取引の訂正開始時は、証憑も添付不可記録もなければ「未添付」とする。
- 新規登録 Drawer と登録後の証憑 Drawer に「証憑添付不可」アクションを置く。
- 「証憑添付不可」を選ぶと理由入力を表示し、保存後は「理由記録済み」とする。
- 理由記録済みの取引にも後から証憑を添付できる。1件以上添付されている間は「添付済み」を優先表示する。
- 添付済み証憑をすべて削除した場合、添付不可記録が残っていれば「理由記録済み」に戻す。
- 添付不可記録は「未添付に戻す」アクションで解除できる。証憑がなければ「未添付」になる。
- 取引内容の通常の訂正では添付不可記録を維持する。訂正 Drawer を開くだけで状態を初期化しない。

## 2. 理由入力

理由は次から必須選択とする。

| 理由ID | 画面表示 | 補足メモ |
|---|---|---|
| `bank_history_expired` | 銀行の閲覧期限超過 | 必須 |
| `not_issued` | 証憑が発行されていない | 任意 |
| `paper_storage` | 紙で別途保存 | 任意 |
| `external_electronic_storage` | 外部システムで電子保存 | 任意 |
| `other` | その他 | 必須 |

補足メモは前後の空白を除去し、1文字以上500文字以下とする。理由が「銀行の閲覧期限超過」の場合は、確認した代替情報や再取得を試した結果を記録するよう案内する。

入力領域には次の注意書きを表示する。

> この記録は証憑の保存義務を免除するものではありません。取得可能な請求書、領収書、銀行明細などは保存してください。

## 3. データモデルとAPI

`admin_finance_expenses` へ添付不可判断を直接持たせず、現在の判断を独立管理する専用テーブル `admin_finance_evidence_unavailable_records` を追加する。変更履歴は後述の管理監査ログで保持する。

| カラム | 内容 |
|---|---|
| `entry_id` | 収入取引ID、主キーかつ取引への外部キー |
| `reason` | 定義済み理由ID |
| `note` | 補足メモ |
| `recorded_at` | 記録日時 |
| `recorded_by` | 記録した管理者 |
| `updated_at` | 更新日時 |
| `updated_by` | 更新した管理者 |

解除時にも監査可能性を残すため、登録・更新・解除を既存の管理監査ログへ記録する。専用テーブルの行は解除時に削除し、解除操作の事実は監査ログに残す。

既存の cost-profit API に、CSRF・MFA・`admin.finance.manage` の認可を継承する次の操作を追加する。

- `evidenceUnavailable.upsert`: 対象取引が手動収入であることをサーバー側で確認し、理由とメモを保存する。
- `evidenceUnavailable.delete`: 対象取引の記録を解除する。

GET は各手動取引に `evidenceUnavailable` を返す。クライアントから送られた取引種別だけを信用せず、DB上の取引を照合する。支出、論理削除済み取引、注文データ由来取引への操作は拒否する。

新規登録では、取引作成が成功してIDを得た後に添付不可記録を保存する。記録保存に失敗した場合は、取引自体は登録済みであることを明示し、再操作できるようにする。

## 4. 状態判定と画面反映

`EvidenceStatus` に `unavailable_recorded` を追加し、純粋関数の判定順を次に統一する。

1. 注文データ由来なら `system_record`
2. 証憑が1件以上あれば `attached`
3. 添付不可記録があれば `unavailable_recorded`
4. それ以外は `missing`

この判定を一覧、証憑ドーナツ、未添付フィルター、CSV、帳簿詳細、税務レポートで共有する。

- 一覧の証憑列は「理由記録済み」を表示し、押すと証憑 Drawer を開く。
- 証憑ドーナツは「添付済み」「理由記録済み」「未添付」の3区分にする。注文データ保存済みは従来どおり証憑充足側として扱う。
- 「証憑未添付」フィルターには `missing` のみを含め、`unavailable_recorded` は含めない。
- 確認キューには「証憑未添付」と別に「証憑添付不可（理由記録済み）」の件数を表示し、税務確認時に見落とさないようにする。
- CSVの証憑列は「理由記録済み」とし、証憑理由と補足メモの列を追加する。
- 帳簿詳細と税務レポートは「添付済み」と同一視せず、「理由記録済み」を独立表示・集計する。

## 5. エラー処理

- 理由未選択、または必須メモ未入力はクライアントとAPIの両方で拒否する。
- 保存中は二重送信を防止する。
- 保存失敗時は現在の表示状態を変えず、Toast に具体的なエラーを表示する。
- 新規取引作成後に添付不可記録だけが失敗した場合は「収入は登録しましたが、証憑添付不可の理由を保存できませんでした。」と表示する。
- 後から証憑を添付しても添付不可記録は削除しない。全削除時の復帰に利用する。

## 6. テスト

- 状態判定の単体テストで4状態と優先順位を検証する。
- migration テストでテーブル、理由制約、外部キー、RLSを検証する。
- APIテストで登録、更新、解除、必須メモ、対象外取引、権限、監査ログを検証する。
- React Testing Libraryで新規登録時の初期「未添付」、理由入力、保存後の「理由記録済み」、後日添付、全削除後の復帰、解除を検証する。
- 一覧、ドーナツ、未添付フィルター、確認キュー、CSV、帳簿、税務レポートが同じ判定を使うことを検証する。
- Playwrightで mobile（390px）、tablet（768px）、desktop（1280px）の操作、キーボード操作、フォーカス、横方向のページスクロールがないことを検証する。

## 7. 対象外

- 銀行APIから過去明細を自動取得する機能
- 税法上の保存義務が免除されたと判定する機能
- 支出取引の証憑添付不可記録
- 注文データ由来取引の状態変更

## 完了条件

手動の収入取引について、未対応の「未添付」と、事情を確認して残した「理由記録済み」を明確に区別できること。理由記録後も証憑を追加でき、証憑をすべて削除すると理由記録済みに戻ること。すべての一覧・集計・出力が同一の状態判定を利用し、「理由記録済み」を「添付済み」と誤表示しないこと。
