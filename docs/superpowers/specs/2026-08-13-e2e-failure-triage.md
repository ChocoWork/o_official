作成日: 2026-08-13

## 測定条件

- `npx playwright test`（全1634件、本番ビルド、直列）
- 結果: **1385 passed / 226 failed / 23 skipped**（1.7時間）
- ビューポート違いの重複を除くとユニーク141件、98スペックファイル

## 前提の確認: 既存のドリフトである

未コミットだった他プランの作業（`SingleSelect` / `TextField` / `TextAreaField` / `types.ts` / `CostProfitSection` / 会計API / `entry-review` / `payment-methods`）をすべて `git stash` で退避し、クリーンビルドで代表7スペックを実行した。

結果は**退避前とまったく同じ6件が失敗**した。

- `FR-ABOUT-001` / `FR-ACCOUNT-002` / `FR-CHECKOUT-001` / `FR-CONTACT-005` / `FR-HEADER-001` / `FR-NEWS-ALL-003`

したがって226件は**今回の作業（ゲスト購入導線の18コミット）とも、未コミットの他プラン作業とも無関係**な、以前から蓄積していた実装とテストの乖離である。退避した作業は測定後に全て復元済み。

## 対処方針の見立て

### 機械的に直せる（テスト側の修正で済む公算が大きい）

**分類1（18件）** — 選択肢は `role="option"` を持つのに、テストが `getByRole('button', { name: '東京都' })` で探している。`getByRole('option', ...)` に直せば通る。原因が1つなので一括で処理できる。

**分類2（42件・ADMIN に集中）** — `getByRole('button', { name: /^CVR/ })` のようなセレクタが複数要素に一致している。画面に同じ文言のボタンが増えたため。`.first()` や絞り込みで解消するが、**どの要素を指すべきかは1件ずつ判断が要る**（誤った要素を掴むテストにすると意味が無くなる）。

#### 分類2の修正結果（2026-08-13）

42件は6 spec・14テスト行に集約されていた。重複要素は、KPI名が旧コンパクト一覧、FREQ-261のKPI一覧カード、選択中KPIサマリーに同時表示されることで発生していた。操作・検証対象はFREQ-261の一覧カードであるため、「KPI一覧」Panel内かつaccessible nameが `KPI名：定義` で始まるボタンへlocatorを限定した。

対象6 spec・63件の再実行結果は60 passed / 3 failed。分類2のstrict-mode violation 42件はすべて解消した。残る3件は `FR-ADMIN-005-kpi-monochrome.spec.ts` の色値不一致であり、セレクタ問題ではないため分類3へ振り替えた。

**分類6（9件・LEGAL）** — 法務ページの文言不一致。実装とテストのどちらが正しいかは**事業判断**（特定商取引法の表記など、法的要件に関わる）。

### 仕様判断が要る

**分類5（62件・最大）** — 期待する要素が存在しない。個別に「実装が未完成なのか、テストが古いのか」を見る必要がある。例:

- `FR-ABOUT-001`: `/about` の本文コピーがテストの期待文言と違う → **どちらの文言が正か**の判断が要る
- `FR-HEADER-001`: desktop で `Open menu` が hidden。デスクトップでハンバーガー非表示は**現在の実装が正しい**と思われ、テストが古い
- `FR-CART-002`: カートに「配送料」が無い → 配送料の表示を仕様として持つかの判断

**分類3（37件）** — 余白・行高・比率などの計測値。デザイン変更に追随できていない。**現在のデザインが正なら**テストの期待値を更新するだけだが、意図せず崩れた可能性も残る。

#### 分類3の再実行結果（2026-08-13）

元の37件に分類2から振り替えたKPI色3件を加え、対象15 spec・59件を再実行した。結果は19 passed / 40 failedで、分類3相当の40件はすべて再現した。

失敗には単なる固定px値の差だけでなく、次の意味的要件違反が含まれる。

- 見出しと本文の文字サイズが同じ
- 注記と本文の文字サイズが同じ
- primary CTAが他の操作要素より低い
- Googleボタンとprimary CTAの高さが揃っていない
- desktopフィルタサイドバーがスクロールに追従しない
- KPIカードに赤・青系の達成状態色が使われ、無彩色要件を満たさない

このため、40件を現在の計測値へ一括更新するのは不適切と判断した。デザイン要件を維持する場合は実装を修正し、現在の表示を正式仕様とする場合だけ対応するテスト期待値を更新する。

### 環境要因の可能性

**分類7（36件）** — タイムアウト。1.7時間の直列実行で後半に集中していないかの確認が要る。個別実行で通るなら環境由来。

#### 分類7の再実行結果（2026-08-13）

分類7に含まれた18 specを、ポート3000の既存サーバーと1 workerでまとめて再実行した。対象spec全体では102件を実行し、83 passed / 19 failed（11.0分）だった。元の分類7に属する36件だけを照合すると、次の結果になった。

| 結果 | 件数 | 対象 | 判断 |
|---|---:|---|---|
| 再現せず通過 | 20 | ADMIN 18、NEWS 1、STOCKIST 1 | 長時間の全件直列実行に伴う環境要因として分類7を解消 |
| 分類5へ振替 | 12 | ACCOUNT 5、CHECKOUT 1、HEADER 3、ITEM-ALL 3 | 現行UIに存在しない文言・操作・レスポンシブ要素を待っている |
| 挙動不良候補 | 4 | ITEM-ALL 017/018 の mobile・tablet | 価格スライダー操作後に `priceMax` がURLへ反映されない。desktopは通過 |

分類5への振替理由は以下のとおり。

- ACCOUNTでは、タブが `button` ではなく `tab` になり、保存ボタンの文言も「変更を保存」から「保存」へ変わっている。ログアウトテストも現行のログアウトボタンではなく古いフォーム送信操作を行っている。
- CHECKOUTはログイン後の遷移待ちが現行フローと一致していない。
- HEADERはdesktopで非表示になる `Open menu` をクリックしようとしている。desktopでハンバーガーメニューを非表示にする現行仕様と矛盾する。
- ITEM-ALL 003/006はdesktopのインラインフィルタ表示に対して、mobile・tablet用の `Open filter drawer` を待っている。

ITEM-ALL 017/018は要素欠落ではない。mobile・tabletではDrawerと価格スライダーが表示される一方、操作後もURL更新が起きず30秒でタイムアウトする。調査の結果、Drawerが開いている間だけ300msデバウンス処理を停止する実装がFREQ-41と矛盾していたため、全viewportで自動適用するよう修正した。ポート3000では既存の本番ビルドが稼働中であり、既存プロセスを維持したままでは修正後JavaScriptのE2E再検証ができないため、fresh serverでの確認を残す。

なお、対象spec全体で発生した19 failuresのうち3件は、`FR-ADMIN-025-expense-templates.spec.ts` に後から追加された未保存確認テストであり、元の分類7の36件には含まれない。

## 着手順の提案

1. **分類1（18件）** — 原因が単一で機械的。まずここで手順を固める
2. **分類7（36件）** — 個別再実行で切り分け。環境由来なら実質ゼロになる可能性がある
3. **分類2（42件）** — ADMIN に集中しており、同じ画面を続けて見られる
4. **分類3（37件）** — デザインの現状を正として期待値を更新
5. **分類5（62件）** — 仕様判断が要るものを抽出し、まとめて確認してから着手
6. **分類6（9件）** — 法務文言。事業判断が要る
