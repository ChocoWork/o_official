作成日: 2026-08-13

## 測定条件

- `npx playwright test`（全1634件、本番ビルド、直列）
- 結果: **1385 passed / 226 failed / 23 skipped**（1.7時間）
- ビューポート違いの重複を除くとユニーク141件、98スペックファイル

## 前提の確認: 既存のドリフトである

未コミットだった他プランの作業（`SingleSelect` / `TextField` / `TextAreaField` / `types.ts` / `CostProfitSection` / 会計API / `entry-review` / `payment-methods`）をすべて `git stash` で退避し、クリーンビルドで代表7スペックを実行した。

結果は**退避前とまったく同じ6件が失敗**した。

- `FR-ABOUT-001` / `FR-ACCOUNT-002` / `FR-CHECKOUT-001` / `FR-CONTACT-005` / `FR-HEADER-001` / `FR-NEWS-ALL-003`

したがって226件は**今回の作業（ゲスト購入導線の18コミット）とも、未コミットの他プラン作業とも無関係**な、以前から蓄積していた実装とテストの乖離である。退避した作業は測定後に全て復元済み。

## 対処方針の見立て

### 機械的に直せる（テスト側の修正で済む公算が大きい）

**分類1（18件）** — 選択肢は `role="option"` を持つのに、テストが `getByRole('button', { name: '東京都' })` で探している。`getByRole('option', ...)` に直せば通る。原因が1つなので一括で処理できる。

**分類2（42件・ADMIN に集中）** — `getByRole('button', { name: /^CVR/ })` のようなセレクタが複数要素に一致している。画面に同じ文言のボタンが増えたため。`.first()` や絞り込みで解消するが、**どの要素を指すべきかは1件ずつ判断が要る**（誤った要素を掴むテストにすると意味が無くなる）。

**分類6（9件・LEGAL）** — 法務ページの文言不一致。実装とテストのどちらが正しいかは**事業判断**（特定商取引法の表記など、法的要件に関わる）。

### 仕様判断が要る

**分類5（62件・最大）** — 期待する要素が存在しない。個別に「実装が未完成なのか、テストが古いのか」を見る必要がある。例:

- `FR-ABOUT-001`: `/about` の本文コピーがテストの期待文言と違う → **どちらの文言が正か**の判断が要る
- `FR-HEADER-001`: desktop で `Open menu` が hidden。デスクトップでハンバーガー非表示は**現在の実装が正しい**と思われ、テストが古い
- `FR-CART-002`: カートに「配送料」が無い → 配送料の表示を仕様として持つかの判断

**分類3（37件）** — 余白・行高・比率などの計測値。デザイン変更に追随できていない。**現在のデザインが正なら**テストの期待値を更新するだけだが、意図せず崩れた可能性も残る。

### 環境要因の可能性

**分類7（36件）** — タイムアウト。1.7時間の直列実行で後半に集中していないかの確認が要る。個別実行で通るなら環境由来。

## 着手順の提案

1. **分類1（18件）** — 原因が単一で機械的。まずここで手順を固める
2. **分類7（36件）** — 個別再実行で切り分け。環境由来なら実質ゼロになる可能性がある
3. **分類2（42件）** — ADMIN に集中しており、同じ画面を続けて見られる
4. **分類3（37件）** — デザインの現状を正として期待値を更新
5. **分類5（62件）** — 仕様判断が要るものを抽出し、まとめて確認してから着手
6. **分類6（9件）** — 法務文言。事業判断が要る
