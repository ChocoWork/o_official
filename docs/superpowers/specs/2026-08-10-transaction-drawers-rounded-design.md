# 取引入力・確認画面の角丸統一設計

## 概要

取引管理タブの「新規取引」Drawer と「取引の確認」Drawer を、中程度の角丸で統一する。配色、余白、情報構造、操作フローは変更しない。実現には既存 UI コンポーネントの `shape` または `radius` props を優先し、既存 API で表現できない場合だけ再利用可能な props を UI コンポーネントへ追加する。

## 対象

- 新規支出・新規収入・取引訂正で共用する取引入力 Drawer
- 要確認理由を表示する取引確認 Drawer
- 両 Drawer 内の入力欄、選択欄、情報カード、操作ボタン

対象外は、取引一覧本体、他タブ、配色、余白、文言、データ処理である。

## デザイン

- Drawer は既存 `Drawer` の `shape="rounded"` を使用し、画面内側の端を 8px 相当で丸める。
- Panel、Button、SingleSelect など既存 UI コンポーネントは、それぞれの `radius="rounded"` または `shape="rounded"` を使用する。
- 入力欄、テキストエリア、情報カードは 8px 相当を基本とする。入れ子の小さなカードは 6px 相当とし、親子の階層を保つ。
- ピル型バッジやラジオボタンなど、意味を持つ既存の完全な丸形は維持する。
- 画面固有の CSS セレクタで UI コンポーネント内部を上書きしない。必要な表現が props に存在しない場合は UI コンポーネント側へ型付き props を追加する。

## コンポーネント方針

既存の `Drawer`、`Button`、`Panel`、`SingleSelect`、`FileDropZone` を再利用する。ネイティブ要素を直接描画している箇所に対応する共通 UI コンポーネントが既にある場合は置き換え、ない場合は現在の UI コンポーネント体系へ最小限の shape props を追加する。

閉じる操作のアイコンボタンも既存 `Button` で表現し、フォーカス表示、44px の操作領域、ARIA ラベルを維持する。種別切替ボタンと保存・取消ボタンも `Button` の shape props で統一する。

## アクセシビリティ

- Drawer の dialog semantics、フォーカス動作、閉じる操作を維持する。
- 入力ラベル、ARIA ラベル、エラー表示、キーボード操作を変更しない。
- 角丸によって境界線やフォーカスリングが欠けないことを確認する。
- モバイル幅でも横スクロールを発生させない。

## テスト

- 既存 UI コンポーネントの shape props が Drawer、Button、入力系要素へ反映されることをテストする。
- 取引入力 Drawer と取引確認 Drawer の主要要素が角丸で描画されることを E2E またはコンポーネントテストで確認する。
- 既存の取引登録、確認済み操作、モバイル表示のテストを再実行する。
- lint、型チェック、関連テスト、ビルドを実行する。

## 完了条件

- 2画面の外枠、入力欄、選択欄、カード、ボタンが中程度の角丸で統一されている。
- 角丸は既存 UI コンポーネントの props を通じて適用されている。
- 既存 props で不足する場合の変更は UI コンポーネントへ閉じ、他画面の既定表示を変えない。
- 操作、レスポンシブ表示、アクセシビリティに回帰がない。
