# 返品の受け取りで品ごとに返金の仕方を選ぶ 設計書

> 対象: 管理画面の返品の受け取り（グループ E-3 の受け取りの画面と DB の関数 `admin_receive_return`）
> 関連: [返品と交換（グループ E-3）設計書](2026-10-12-returns-design.md)、[割引（グループ H）設計書](2026-10-28-group-h-promotions-design.md)、[会計の計画3](../plans/2026-11-04-accounting-p3-returns-refunds.md) の未確認 #17

## 概要

返品の荷物を受け取る時に、届いた品ごとに「今すぐ返金」か「額を相談」を選べるようにする。あわせて、受け取りの「今すぐ返金」の額の上限を「今すぐ返金にした品の額＋送料」に絞る。

| 項目 | 内容 |
| --- | --- |
| なぜ | 同じ箱で2点届き、1点に傷がある時に、きれいな方はすぐ返し、傷のある方はお客様と相談してから返したい。今は受け取り1回につき返金の仕方が1つしか選べない |
| もう1つのなぜ | 前に相談にした品の分を、後の受け取りの「今すぐ返金」にまとめて入れられる。これが会計の計画3の未確認 #17 の曖昧さ（どの品の返金か帳簿で分からない）を生む |
| 画面 | 品の行の中、品の状態のすぐ下に「返金: 今すぐ返金 / 額を相談」を置く（見本の A。オーナーが選んだ） |
| 押した後 | 「受け取る」を1回押せば、届いた品は全部「受け取り済み」。今すぐ返金の品はすぐ返金、相談の品は「返金待ち」 |
| 上限 | 今すぐ返金の額 ≤ 今すぐ返金にした品の額＋送料（さらに注文の返せる額まで） |
| 出し分け | 権限「返金」（`admin.orders.refund`）で決める。役割の名前では決めない。持つ人には品ごとの選びと額の入力を出す。持たない人は、今の自動の返金（P9）が許される返品だけ品ごとの選びを出し、額の入力は出さない（3-3） |
| 記録の形 | 1回の受け取り＝受け取りの行1つ（届いた事実は1つ）。返金の選びは受け取りの明細（品）ごとに持つ |
| 順番 | 会計の計画3より前に入れる。入れたら計画3の #17 を「済み」にし、計画3の受け取りの前提を直す |

## 1. 目的と、しないこと

### 1-1 目的

- 届いた品ごとに、すぐ返すか、相談してから返すかを店が選べる
- 受け取りの「今すぐ返金」で、その受け取りの品と関係ない額（前に相談にした品の分など）を返せないようにする
- 帳簿（会計の計画3）で、どの返金がどの品の分かを曖昧にしない

### 1-2 しないこと

- 「額を決めて返金する」（相談の後の返金、`admin_refund_return`）の対象と上限は変えない。今までどおり、その返品の返金待ちの品全部を対象にし、上限は注文の返せる額
- 返品の手数料・返送料・交換の手数料・交換の送料の決め方（返品を作る時に決まる）は変えない
- お客様の画面（返品の申し込み）は変えない
- 権限の初期の割り当て（店長・サポートの組）は変えない

### 1-3 失敗とみなすこと

- 1回押したのに、受け取りが2回あったように見える（履歴が2行、メールが2通に分かれる）
- 相談にした品まで、すぐ返金されてしまう
- 権限「返金」を持たない人が、額を直せたり、相談の品を今すぐ返金にできたりする

## 2. Shopify・業界の例との比べ

調べた日は 2026-11-06。詳しくは調べのメモ（作業場所の `shopify-research.md`）。

| 項目 | Shopify | 業界の例 | この設計 | 出典 |
| --- | --- | --- | --- | --- |
| 同じ返品の一部だけ今返し、残りを後で返す | できる。返品の一部の品だけ処理して返金し、残りは後で処理・返金する（確定）。品ごとの「今返金・保留」の欄は無い（有力） | WooCommerce は品ごとに数・額を入れて何度でも返金（有力） | 品ごとに「今すぐ返金・額を相談」を選ぶ。Shopify の「一部だけ先に処理」を1回の操作でできる形 | [processing-returns](https://help.shopify.com/en/manual/fulfillment/managing-orders/returns/processing-returns)、[WooCommerce refunds](https://woocommerce.com/document/woocommerce-refunds/) |
| 返金を何回にも分ける | できる（確定） | 同上 | できる（今までどおり） | [refunding-orders](https://help.shopify.com/en/manual/fulfillment/managing-orders/refunding-orders) |
| 返金額の上限 | 注文の返せる残りまで。選んだ品の額では止めない（有力） | Amazon は品ごとに返す額を入れる（暫定・掲示板） | 今すぐ返金にした品の額＋送料まで（注文の残りも超えない）。Shopify より厳しい。意図した違い（1-1 の2つ目） | 同上 refunding-orders |
| 送料の返金 | 品とは別の欄。上限は送料の返せる残り（確定） | — | 同じ（今の「送料」の欄のまま） | 同上 refunding-orders |
| 返品の権限と返金の権限 | 別の権限（確定） | — | 同じ考え方。品ごとの選びと額の入力は権限「返金」で出す | [store-permissions](https://help.shopify.com/en/manual/your-account/users/roles/permissions/store-permissions) |

Shopify より厳しい上限にしたことで、品と関係ない上乗せ（おわびの額など）は受け取りの画面では返せない。その時は、ふつうの返金の画面か「額を決めて返金する」を使う。

## 3. 画面（受け取りの画面 `OrderReturnReceiveDialog`）

### 3-1 品の行

- 今の行（品名・「届いた」・「品の状態」）の下に、「返金: ◉ 今すぐ返金 ○ 額を相談」を足す
- 出すのは、チェックを入れた品のうち、返金になる品（解決が返金の品と、交換を「返金に変える」にした品）だけ。交換の品・お返しの品には出さない
- 最初の値は「今すぐ返金」
- 同じ品が2点ある時も、今と同じく1点1行で並ぶので、1点ずつ選べる

### 3-2 返金の欄

- 「今すぐ返金（n点）」: 内訳（商品・返品の手数料・返送料など・送料）と返金額の入力。返金額の入力の上限を示す（「上限 ￥X」）
- 「額を相談（m点）」: 品名を並べ、「返金待ちになります。額はあとで「額を決めて返金する」で決めます。」
- 上限を超える額を入れたら、欄の下に「この受け取りの商品の額と送料（￥X）を超えて入れられません。ほかの受け取りの分は、返品の画面の「額を決めて返金する」で返してください。」を出し、直るまで押せない
- ボタンの言葉: 両方ある時は「受け取る（n点を ￥X 返金・m点は相談）」。片方だけの時は今の言葉のまま

### 3-3 権限での出し分け

| 人 | 品ごとの選び | 返金額・送料の入力 |
| --- | --- | --- |
| 権限「返金」を持つ人 | 出す | 出す（上限は 4-2） |
| 持たない人で、今の自動の返金（P9: お客様の申し込みの返品で、返送不要でない）が許される時 | 出す | 出さない（額は計算どおり） |
| 持たない人で、上の条件に当たらない時 | 出さない（今までどおり全部「相談」） | 出さない |

権限は、管理画面の権限の設定で役割ごとに変えられる（今の仕組みのまま。窓口が `admin.orders.refund` を確かめて `canRefund` を返す）。持たない人の行の形はオーナーとの会話での私（設計者）の判断。

## 4. 額の決め方

### 4-1 記号

| 記号 | 意味 |
| --- | --- |
| G今 | 今すぐ返金にした品の額（割引の後の1着ごとの額。グループ H の決まりで、その返品行が確保した着から取る） |
| G相 | 額を相談にした品の額 |
| F今 | 今すぐ返金の分から引く手数料（4-3） |
| S | 店が入れた送料の返金 |

### 4-2 上限と計算どおりの額

- 計算どおりの今すぐ返金の額 = max(G今 − F今, 0) + S
- 入力できる上限 = min(注文の返せる額, G今 + S)
- 手数料を負けて多めに返すのは、この上限の中でできる（G今 − F今 + S より多く、G今 + S まで）
- 送料 S の上限は今までどおり、注文の返せる送料の残り。S ≤ 返金額も今までどおり
- 上限の確かめは、画面・DB の受け取りの関数の両方で行う。正しいのは DB（窓口は品の額を知らないので形だけ確かめる）

### 4-3 手数料の分け方（設計者の判断）

| 手数料 | 決め方 |
| --- | --- |
| 返品の手数料（%） | 今すぐ返金の分と相談の分で別々に計算し、それぞれ切り捨てる（floor(G今 × p / 100)、floor(G相 × p / 100)）。今の「受け取りごとに切り捨て」と同じ考え方で、お客様に不利にならない |
| 返送料・交換の手数料・交換の送料（最初の受け取りだけに掛かる物） | 今すぐ返金の分があれば、そこから先に引く（F今に入れる） |
| 今すぐ返金の分で引ききれなかった手数料 | 同じ受け取りに相談の分があれば、相談の分の「後で引く手数料」（`fee_pending_deduction`）に足す。相談の分が無ければ今までどおり「お支払い待ち」（`fee_due_amount`） |
| 相談の分の返品の手数料 | 今までどおり `fee_pending_deduction` に足し、「額を決めて返金する」の時に引く |

### 4-4 同じ品を割引で違う額で買っている時

グループ H の決まり（その返品行が確保した着を使う）を保つ。同じ返品行の中で今すぐと相談に分かれた時は、確保した着のうち安い着から今すぐ返金の分に当てる（返金は安い単位から、という H の決まりと同じ向き）。画面の見込みも同じ順で出す。

## 5. 記録の形

### 5-1 受け取りは1つ、選びは品ごと

- 1回押した受け取りは、今までどおり受け取りの行（`order_return_receipts`）1つ、二重防止の番号1つで記録する
- 受け取りの明細（`order_return_receipt_lines`）に、返金の選びの列（`now` / `consult`、返金にならない品は空）を足す。同じ返品行が今すぐと相談に分かれる時は、明細を2行にする
- 受け取りの行の `refund_choice` は、まとめの値にする: 全部今すぐなら `now`、全部相談なら `consult`、両方あれば `mixed`（新しい値）、返金の品が無ければ `none`
- 前からある受け取りの明細（新しい列が空）は、受け取りの行の `refund_choice` に従うものとして読む。受け取りの表は追記だけ（書き換え禁止）なので、前の行は書き換えない
- 今すぐ返金の分の返金（`order_refunds`）は1件。受け取りの行の `refund_id` に今までどおり結び付ける
- 相談の品は「返金待ち」になる。今の返品の状態の決め方（返金待ちがあれば閉じない）で、返品は「返金待ち」のまま開いている
- 同じ注文の行の品が返品の2行に分かれている時（分けて発送した同じ品など）、返品の画面の「返金済み」「返金待ち」の印は、今の数え方（`private.order_return_line_states_core`。返金を行を作った順に割り当てる）のままにする。片方を相談・もう片方を今すぐにすると、印が選んだ行と入れ替わって見えることがあるが、返したお金と枚数は正しい。今でも2回に分けて受け取ると同じ見え方になる。数え方の芯は直さない（2026-11-06 オーナー決定。案「イ」）。この見え方は試験で固定する

### 5-2 なぜ受け取りを2つに分けないか

- 店が見るのは1回の受け取り。2つに分けると、履歴の行・メール・二重防止の番号・在庫の台帳の行・交換の在庫の判定が2回分になり、1-3 の失敗に当たる
- 会計の計画3は「届いた事実は受け取りごとに1つ」を前提にしている。品が届いたのは1回なので、受け取りの行も1つの方が事実に合う

### 5-3 DB の関数

- 新しい移行で `admin_receive_return` を作り直す（適用済みの移行は書き換えない）。引数 `_units` の要素に返金の選び（`refund_choice`）を足す。受け取り全体の `_refund_choice` は、品ごとの選びを送らない呼び出し（前の画面・試験）のための既定として残す
- 権限「返金」を持たない人（`_actor_can_refund = false`）が、P9 の条件に当たらないのに `now` の品を送ったら断る（今の決まりの品ごと版）
- 上限（4-2）を超える指定額は、入力の誤りとして断る（新しい断りの記号）
- 返り値の形は変えない（受け取りの番号1つ・返金1つ）

## 6. 知らせ・履歴

| 物 | 決め方 |
| --- | --- |
| お客様へのメール | 1回の受け取りで1通。今すぐ返金が正の額なら、今までどおり返金のメールに受け取りの内容を入れ、相談の品には「この品は状態を確かめてから、あらためてご連絡します」の一文を添える。今すぐ返金が0円や失敗の時は、今までどおり受け取りのメールにし、品ごとに返金の分と相談の分を分けて書く |
| お店への知らせ | 権限「返金」を持たない人が相談の品を含めて受け取った時は、今までどおり店長への知らせ（返金待ち）を出す |
| 注文の履歴 | 「返品の受け取り」は1行。細目に「今すぐ返金 n点・相談 m点」を足す |
| 在庫の台帳 | 変えない（在庫に戻す品だけ、受け取り1回分をまとめて足す） |

メールの文面の細かい言葉は、実装の時に今の文面に合わせて決めてよい。

## 7. 会計の計画3への影響

| 計画3の前提 | 直し方 |
| --- | --- |
| 届いた事実（arrival）は受け取りごとに1つ | そのまま |

- 要求・受け入れ条件: 管理画面は範囲（`scripts/trace/scope.json` の ADMIN）に入っているので、`docs/02_Requirements/areas/admin.md` に新しい要求（`SR-ADMIN-NNN`）として書く

- 受け入れ条件の例:
  - 2点を同じ受け取りで、1点を今すぐ返金・1点を相談にすると、1点分だけ返金され、もう1点が返金待ちになること
  - 注文の履歴の「返品の受け取り」が1行であること
  - 今すぐ返金の額に、今すぐ返金にした品の額＋送料を超える額を入れると、文が出て押せないこと。DB も断ること
  - 上限ちょうどの額は返せること
  - 権限「返金」を持たない人には、額の入力が出ないこと
  - 同じ注文の行の品が返品の2行に分かれ、片方を相談・片方を今すぐにした時、返金は1点分で、返金待ちが1点残ること（どちらの行に印が付くかは今の数え方のまま。5-1）
- 直す必要がある今の試験は、調べのメモ（作業場所の `research-report.md` の 10章）の一覧から計画で選ぶ
