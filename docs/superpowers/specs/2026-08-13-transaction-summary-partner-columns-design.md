# 取引管理の摘要・取引先列分離設計

## 概要

Admin ページの取引管理テーブルで、現在ひとつの列に表示している「摘要・取引先」を「摘要」と「取引先」の独立した列に分ける。取引一覧に限って列間隔を狭め、PC・タブレット・スマートフォンのすべてでセル内容を折り返し・省略せず表示する。画面幅に収まらない場合は、既存のテーブルコンテナ内で横スクロールして閲覧できるようにする。

## 対象

- `CostProfitSection` の取引管理テーブル
- 手動登録した収入・支出
- Supabase 注文を出所とする読み取り専用取引

## UI設計

- 列順を次のとおりとする。
  - 選択
  - 日付
  - 種別
  - 勘定科目
  - 摘要
  - 取引先
  - 金額
  - 証憑
  - 更新履歴
  - 状態
  - 操作
- 摘要列には `entry.item`、取引先列には `entry.partner` を表示する。
- 取引先が未設定の場合は、既存の取引詳細表示と同じ「取引先なし」を表示する。
- 摘要列と取引先列から最大幅および省略表示を取り除き、ヘッダーと本文を折り返し禁止にする。
- Supabase 注文の「Supabase注文」および返金額の補足は摘要列内に残す。補足同士は必要に応じて横方向に並べ、セル内では折り返さない。
- 日付・種別・勘定科目・金額・証憑・更新履歴・状態・操作は内容に近い幅に保ち、取引一覧だけセル左右余白を縮小する。
- 共通 `DataTable` の既定スタイルは変更せず、他画面の表へ影響させない。

## レスポンシブ動作

- PC・タブレット・スマートフォンで同じ列構成を使用する。
- 全列の本文を折り返し禁止とし、省略記号を表示しない。
- 表に内容を保持できる最小幅を設定する。
- ビューポートより表が広い場合は、既存の `DataTable` コンテナの横スクロールを利用する。
- 行選択、証憑、状態確認、編集、削除の既存操作は維持する。

## 実装方針

- 取引一覧の `entryColumns` で摘要と取引先を別々の列定義にする。
- 取引一覧の列定義と `tableClassName`／`containerClassName` の局所的なクラス指定だけで幅・余白・折り返しを制御する。
- `DataTable` の props や共通 CSS に新しい仕様は追加しない。
- データ取得、保存、状態判定、ページングには変更を加えない。

## テスト

- 取引管理テーブルに「摘要」と「取引先」の独立した列見出しがあること。
- 同一行で摘要と取引先がそれぞれ独立したセルに表示されること。
- 取引先未設定時の代替表示が取引先セルに表示されること。
- 摘要・取引先セルに省略表示のクラスがなく、折り返し禁止になっていること。
- 取引一覧に横スクロール可能な最小幅と局所的な狭いセル余白が設定されること。
- Supabase 注文の補足表示と既存の行操作が維持されること。

## 対象外

- 取引入力 Drawer の項目構成
- 取引データの保存形式や API
- 取引管理以外のテーブル余白
- 状態・証憑・更新履歴の判定ロジック
