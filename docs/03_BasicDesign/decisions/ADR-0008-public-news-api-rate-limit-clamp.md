# ADR-0008 `GET /api/news` に回数の制限と件数の上限を付け、正しくない件数は既定か上限に丸める

> 状態: 現行 | 確認日: 2026-10-24 | 対象: `src/app/api/news/route.ts` | 基準コミット: `a03beaff`

## 概要

認証の無い `GET /api/news` に10分60回の回数の制限と最大20件の上限を付け、件数の指定が正しくない時は断らずに既定の12件か上限に丸める。

## 判断

### ADR-0008 `GET /api/news` に回数の制限と件数の上限を付け、正しくない件数は既定か上限に丸める

| 属性 | 値 |
| --- | --- |
| 上位 | SEC-NEWS-009、DRV-NEWS-007 |
| 根拠 | 認証の無い窓口で件数の上限も回数の制限も無いと、まとめて吸い出され DB の負荷が増えるため（2026-04-18 のレビューの Priority 1）。件数を丸める形にしたのは、レビューが「400 で断る」と「決めた上限に黙って丸める」のどちらでもよいとしたため |
| 状態 | 現行 |
| 出どころ | `docs/05_Quality/reviews/code/2026-04-18-news-id-security-review.md`、git `8c6e210e`（2026-04-19） |

#### 背景

`/api/news` は呼ぶ側が `limit` を決められ、回数の制限も無かった。

#### 決定

- `enforceRateLimit` を `news:list`・10分に60回で掛ける（`route.ts`）
- `limit` は数字だけを受け、1〜20 に収める。無い・正しくない時は 12（`route.ts`）

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 正しくない・大きすぎる `limit` を 400 で断る | レビューが並べた2つの案の片方。選ばなかった理由の記録は無い（推定: 呼ぶ側を壊さずに上限を守れる） |

#### 結果

- 良くなること: この窓口からは1回に20件までしか取れない
- 悪くなること: 公開の一覧のページはこの窓口を通らず DB から直接取るので、回数の制限も件数の上限も効かない（ADR-0021、`security_review_news.md`）
- 悪くなること: anon は PostgREST や `search_news` から直接読める（SEC-NEWS-010）。回数の制限の送り元の IP は見出しから取るので偽れる（SEC-NEWS-011）
- 悪くなること: 今の画面はこの窓口を呼ばず、検索の E2E の補助だけが使う（DRV-NEWS-007）
