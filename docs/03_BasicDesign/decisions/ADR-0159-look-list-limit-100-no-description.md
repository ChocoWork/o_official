# ADR-0159 LOOK の一覧は 100 件まで取り、説明文を取らない（価格は残す）。詳細は 1 件で取り、前後は 1 件ずつ取る

> 状態: 現行 | 確認日: 2026-10-26 | 対象: `src/lib/look/server.ts`、`src/lib/look/public.ts`、`src/app/look/page.tsx`、`src/app/look/[id]/page.tsx`、`src/app/look/error.tsx` | 基準コミット: `4fe88539`（作業ツリーに別の作業の未コミットの差分あり）

## 概要

`/look` は公開の LOOK を新しい順に最大 100 件だけ取り、一覧では使わない説明文を取らない。関連商品の価格・名前・画像は今のカードが出すので残す。詳細の頁は現在の LOOK を 1 件で取り、前後の LOOK は並びの境目から 1 件ずつだけ取る。取り出しの失敗は「0 件」にせず、誤りの画面に出す。

## 判断

### ADR-0159 LOOK の一覧は 100 件まで取り、説明文を取らない（価格は残す）。詳細は 1 件で取り、前後は 1 件ずつ取る

| 属性 | 値 |
| --- | --- |
| 上位 | SEC-LOOK-009、SEC-LOOK-016、SEC-LOOK-022 |
| 根拠 | 一覧の取り出しと署名の重さに上限を付け、端末に渡す中身から一覧で使わない説明文を外すため。LOOK が増えても 1 回の表示の重さを一定に保つ（THR-LOOK-009）。ユーザーが 2026-10-26 に決めた（Q11）: 価格は今のカードが出すので残し、守りの要件のほうを直す。シーズンの絞り込みは今のまま画面の側で行い、100 件を超えたら見直す |
| 状態 | 現行 |
| 出どころ | ユーザーの決定（2026-10-26、波 1-C の決定の 1。上限 100・説明文を外す・価格は残す）。詳細を 1 件で取り前後を 1 件ずつ取る形は、その決定を実現する実装の判断で、計画のレビューで足した。`.superpowers/sdd/2026-10-25-security-gap-fixes/wave1c-decisions.md` |

#### 背景

- ADR-0152 のとおり、一覧は公開の LOOK を件数の上限なしに全部取り、詳細の頁もその全件の中の位置で前後を決めていた。一覧に説明文と関連商品を全部載せて端末へ渡していた
- 上限を付けるだけでは、詳細の頁が一覧の写しに頼っているため、(a) 一覧から説明文を外すと詳細の説明文が空になり、(b) 101 番目より古い LOOK の詳細が「Look not found」になる

#### 決定

- `/look` は `getPublishedLookList` で、説明文を除いた列（`id,season_year,season_type,theme,image_urls,created_at`）を `created_at` の降順・同じ時刻は `id` の降順で 100 件まで取る。型は `PublicLookListItem`（説明文なし）で、説明文が要る詳細だけが `PublicLook` を使う
- ホームの `getPublishedLooks(limit)` も同じ列と並びで、件数を 1〜100 に丸める。失敗は空の配列のまま（ホーム全体を落とさない）
- 詳細の頁は現在の LOOK を `getPublishedLookById`（説明文あり）で 1 件取り、前後は `getAdjacentPublishedLooks` で並びの境目（`created_at` が新しい／古い、同じ時刻なら `id` が大きい／小さい）から 1 件ずつ、`id` と題だけ取る。時刻は PostgREST の予約文字（`.` `:`）を含むので値を二重引用符で囲む。値は DB から読んだ `created_at` と数の `id` だけで、外から来た文字を入れない
- 詳細の `id` は `parseLookId` で正の整数に確かめ、合わなければ DB を呼ばずに「Look not found」にする
- 取り出しの失敗（`looks`・`look_items`・`items`）は名前と符号だけ記録して `LookFetchError` を投げ、`src/app/look/error.tsx` の誤りの画面に任せる。前後の取り出しの失敗は添え物なので記録だけにしてその側を無効にする

#### Shopify との突き合わせ

| 観点 | Shopify の一般的な形 | この判断 |
| --- | --- | --- |
| 一覧の件数 | コレクションの一覧は 1 頁の件数に上限を持つ（Liquid の `paginate` は 1 頁 50 件まで、Storefront API の `first` は 250 件まで。出典は未確認） | 100 件で切る。頁分けは付けない（LOOK は季節ごとに数件ずつしか増えない） |
| 一覧に載せる項目 | 一覧には題・画像・価格など一覧で使う項目だけ。本文は商品ページで取る | 説明文を一覧から外し、カードが出す価格・名前・画像は残す |
| 詳細の前後 | 前後の商品は詳細の頁で別に取る | 前後を 1 件ずつ取る |
| 取り出しの失敗 | 障害は 0 件の表示にせず誤りの頁にする | 誤りの画面に出す |

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 上限を付けるだけで、詳細は一覧の写しから選ぶ | 101 番目より古い LOOK の詳細が開かなくなる。説明文も外せない |
| 詳細で全件（説明文あり）を取り直して位置で選ぶ | 一覧の上限が意味を失い、署名の数も減らない |
| 前後を位置ではなく id の大小で決める | 一覧の並び（作った日時）と食い違う |
| 価格も一覧から外す | 今のカードが出す。ユーザーが残すと決めた（Q11） |
| 頁分けか追加の読み込みを付ける | 100 件を超えるまで要らない。FR-LOOK-ALL-003（COULD）は ADR-0152 のとおり別 |

#### 結果

- 良くなること: 一覧の取り出しと署名が 100 件までに収まる。端末に渡す中身から一覧で使わない説明文が外れる。どの LOOK の詳細も開き、前後も持つ。障害が「LOOK はまだありません」に見えない
- 悪くなること: 101 件目より古い LOOK は一覧に並ばない（詳細の URL では開く）。シーズンで絞っても 100 件の中の絞りになる。詳細の表示で DB の問い合わせが 2 件（前後）増える。本物の PostgREST での `.or()` の時刻の引用が通るかは単体のモックでは文字しか確かめられない
- 見直す条件: 公開の LOOK が 100 件を超えそうな時（頁分けか季節ごとの取り出しに替える）、詳細の前後の 2 件が表示の遅さに響く時
