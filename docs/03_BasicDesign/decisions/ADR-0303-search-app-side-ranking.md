# ADR-0303 結果の並びは、DB から新しい順に受け取り、アプリで点を付けて並べ直す

> 状態: 推定 | 確認日: 2026-10-24 | 対象: `src/features/search/services/search.service.ts` | 基準コミット: `4e84d5c5`

## 概要

DB の検索の関数は新しい順に上限まで返すだけで、関連の強さの順は決めない。アプリの `rankText` が題の頭の一致・題の中の一致・語ごとの一致に点を付け、点の高い順に並べ直す。この形を選んだ理由の記録は無い。

## 判断

### ADR-0303 結果の並びは、DB から新しい順に受け取り、アプリで点を付けて並べ直す

| 属性 | 値 |
| --- | --- |
| 上位 | DRV-SEARCH-001 |
| 根拠 | 要件は並び順を決めていない。部分一致の DB の関数（ADR-0301）は関連の強さの値を持たないので、題の頭に語がある物を先に出すため、アプリで点を付けて並べ直したと推定。DB の側で関連の強さの順にしなかった理由の記録は無い |
| 状態 | 推定 |
| 出どころ | 実装から推定（`src/features/search/services/search.service.ts`） |

#### 背景

DB の関数は、商品・ルックは作った日、ニュースは公開日の新しい順に `limit_count` 件を返す（`remote_schema.sql`）。それだけでは、語が題の頭にある物も本文に1回出るだけの物も同じ扱いになる。

#### 決定

- 語全体の一致に 40 点、題が語で始まれば 80 点（含むだけなら 50 点）、空白や記号で区切った1語ごとに題なら 18 点・ほかの欄なら 8 点を足す（`search.service.ts`）
- 語全体も全部の語も当たらない行は 0 点で捨てる
- 種別ごとに点の高い順に並べ、上限で切る。サジェストも同じ点で並べる

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| DB の側で関連の強さの順にする（`ts_rank`・`similarity` など） | 理由の記録は無い。部分一致の関数には順位の値が無い（推定） |
| DB の新しい順のまま出す | 語が題に無い物が先に来ることがある（推定） |

#### 結果

- 良くなること: DB の関数を変えずに、並び方をアプリで変えられる
- 悪くなること: DB が新しい順に上限で切った後で並べ直すので、上限の外にある、より語に合う古い行は出ない
- 悪くなること: 「N RESULTS」の数は上限で切った後の数（`search.service.ts`）。1種別8件の上限（`src/app/api/search/route.ts`）と LOAD MORE の8行が同じなので、種別のタブでは LOAD MORE が出ない（推定）
