# ADR-0103 ヒーローの縦線は1回で止めず、消える瞬間の無い伸びる動きを繰り返す

> 状態: 推定 | 確認日: 2026-10-24 | 対象: `src/app/page.tsx`、`src/styles/globals.css`（共有） | 基準コミット: `a03beaff`

## 概要

ヒーローの SCROLL の下の縦線は、loading の頁の THREAD DRAW を1回だけ引く形（FREQ-278）から、上端から伸びる動きだけを途切れずに繰り返す形（FREQ-282）へ変えた。動きを減らす設定では止める。

## 判断

### ADR-0103 ヒーローの縦線は1回で止めず、消える瞬間の無い伸びる動きを繰り返す

| 属性 | 値 |
| --- | --- |
| 上位 | FREQ-282-REQ-01、FREQ-282-REQ-02 |
| 根拠 | 1回引いて止まる線では、下へ読む誘いが最初の数秒で終わる。かといって0から引き直す繰り返しでは、線が消える瞬間がちらつき、静かな世界観に合わない。そこで僅かに残した長さから伸ばし、引ききって少し待ってから折り返す動きを繰り返す（FREQ-282 の要件の文）。動きを嫌う人の設定では止める |
| 状態 | 推定 |
| 出どころ | `docs/02_Requirements/requirements.md`（「要求トレーサビリティ追記（LOGIN 2FA・登録/ログイン分離）」節の FREQ-282 の行。ユーザーの依頼の行） |

#### 背景

- FREQ-278 は、縦線を loading の頁の THREAD DRAW（threadDraw）で上から下へ引き、デモ用の無限の再生ではなく1回だけ再生する、と決めた（FREQ-278-REQ-02・06）
- UI/UX レビューは、ブランドに合わせて動きを最小限にすると書いている（`uiux_review_home.md`）

#### 決定

- 縦線には heroThreadLoop を無限に当てる。上端を起点にし、始点は長さ0ではなく僅かに残した長さ（8%）、2.1秒の約78%で引ききり、残りは引ききったまま待つ。速さは ease-in-out（`globals.css`）
- 動きはクラス（hero-thread）で当て、頁の側は要素にクラスを付けるだけにする（`page.tsx`）
- 動きを減らす設定では、SCROLL の文字と縦線の動きを止める（`globals.css`）

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| threadDraw を1回だけ再生して止める（FREQ-278-REQ-06 の形） | 下へ読む誘いが続かない。FREQ-282 で置き換えた |
| loading の頁のデモのように threadDraw を無限に繰り返す | 毎回長さ0から引き直すので、線が消える瞬間ができる（FREQ-282 の「途中で消える瞬間が無い」に反する） |

#### 結果

- 良くなること: 線が消えずに静かに下を指し続ける
- 悪くなること: 動きが止まらないので、「動きは最小限」の方針とは程度の兼ね合いになる（推定）。動きを減らす設定の人には止まる
- FREQ-278-REQ-02・06 と AC-02・06 は今の作りと合わない。置き換えた物として「廃止」にするかはユーザーが決める
- 動きは共有の `globals.css` にあり、HOME の範囲のコードには無い。直しが共有のファイルに入る
