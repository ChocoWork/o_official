# ADR-0100 ホームの ITEM・LOOK は画面の幅に依らず決まった件数を取り、幅ごとの出し分けは CSS で行う

> 状態: 推定 | 確認日: 2026-10-24 | 対象: `src/app/page.tsx` | 基準コミット: `a03beaff`

## 概要

ホームの ITEM・LOOK の区画は、サーバーでどの幅でも同じ件数（ITEM 10件・LOOK 8件）を取り、どの幅で何件を見せるかは描いた後の CSS で決める。サーバーは閲覧者の画面の幅を知らないため。

## 判断

### ADR-0100 ホームの ITEM・LOOK は画面の幅に依らず決まった件数を取り、幅ごとの出し分けは CSS で行う

| 属性 | 値 |
| --- | --- |
| 上位 | FREQ-147-REQ-01、FREQ-147-REQ-02、FREQ-148-REQ-01、FREQ-148-REQ-02 |
| 根拠 | ホームはサーバーで描くので、取る時点では閲覧者の画面の幅が分からない。幅で取る件数を変えるには端末で取り直すか幅を当て推量するしかなく、どちらも最初の表示を遅らせるか外す。そこで一番広い幅の数だけ取り、見せる数は CSS で絞る（FREQ-147・148 の要求の文） |
| 状態 | 推定 |
| 出どころ | `docs/02_Requirements/requirements.md`（「要求トレーサビリティ追記（LOGIN 2FA・登録/ログイン分離）」節の FREQ-147・148 の行。ユーザーの依頼の行）、`src/app/page.tsx` のコメント |

#### 背景

- ホームの ITEM・LOOK の区画は、幅ごとに見せる件数が違う（FREQ-147・148）。NEWS は全部の幅で6件（FREQ-149）
- ホームの頁はサーバーで描き、7つの公開の取得（ITEM・LOOK・NEWS の中身と総数、取扱店）を一度に待つ（`page.tsx`）

#### 決定

- 取る件数は定数で決める。ITEM 10件、LOOK 8件、NEWS 6件（`page.tsx`）
- 取った物は各領域の格子（`PublicItemGrid`・`PublicLookGrid`・`PublicNewsGrid`、範囲外）に渡し、幅ごとに見せる数は CSS のクラスで出し分ける
- VIEW ALL を出すかも同じく、総数と幅ごとの表示数を比べた CSS のクラスで決める（ADR-0105）

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 端末で幅を測ってから、その幅の数だけ取り直す | 最初の表示が空か仮の物になり、取り直しの分だけ遅れる。サーバーで描く利点を捨てる（推定） |
| 送られてきた端末の種類から幅を当て推量し、サーバーで取る数を変える | 同じ端末でも窓の幅は変わり、外れると件数が合わない（推定） |

#### 結果

- 良くなること: どの幅でも1回の取得で描け、幅を変えても取り直さない
- 悪くなること: 狭い幅では見せない分まで取って描く。ITEM は10件を取るが、格子の側は8件までしか描かない（FREQ-276 で見せる数を変えた後、取る数の10が残った。TM-HOME-01・03）
- 7つの取得を一度に待つので、1つの失敗の扱いは SEC-HOME-014 が持つ
- ITEM の取得は在庫の読みに乗るので、在庫の仕組みの改修で件数や VIEW ALL の結果が変わりうる（推定）
- 見せる数を変える時は、取る数の定数（`page.tsx`）と格子の側の描く数・CSS のクラスを一緒に直す
