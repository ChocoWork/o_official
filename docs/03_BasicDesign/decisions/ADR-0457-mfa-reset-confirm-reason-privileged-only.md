# ADR-0457 2要素のリセットは確認の語と理由を求め、自分自身と一般の利用者を断る

> 状態: 推定 | 確認日: 2026-10-26 | 対象: `src/app/api/admin/users/mfa/reset/route.ts` | 基準コミット: `4facf63b`（2026-10-26 に `77e7f844` の作業ツリーで更新）

## 概要

店長が店長・サポーターの2要素の登録を全部消す窓口は、確認の語 `RESET_MFA` と 10〜500 字の理由を求める。自分自身のリセットと、店長・サポーターでない利用者のリセットは断り、どの結果も監査に残す（理由の文・対象のメール・誤りの文は残さず、理由は長さとハッシュだけ。ADR-0461）。対象の役割は DB の ACL（`user_roles`）で決め、全部消せた後は対象の全 session を失効させる（ADR-0461）。

## 判断

### ADR-0457 2要素のリセットは確認の語と理由を求め、自分自身と一般の利用者を断る

| 属性 | 値 |
| --- | --- |
| 上位 | DRV-ADMIN-002 |
| 根拠 | 2要素を消すと、その特権の利用者はパスワードだけで入り直して登録し直せる。取り返しがつかないので、確認の語で取り違えを防ぎ、理由を監査に残して後で確かめられるようにする。自分自身を断るのは、乗っ取った人が自分の2要素を外して居座るのを防ぐため。一般の利用者には2要素が無いので対象にしない（推定。判断の記録は無い） |
| 状態 | 推定 |
| 出どころ | 実装から推定（`src/app/api/admin/users/mfa/reset/route.ts`）、git `bbfb6143`（2026-05-10「Add security best practices and MFA management endpoints」） |

#### 背景

- 店長とサポーターはログインで2要素を求められる（FR-LOGIN-007、範囲外）。認証のアプリを失くすと管理画面に入れない
- 2要素の一覧と削除は Supabase の管理の機能で、service role でしか呼べない（ADR-0451）

#### 決定

- 本文は利用者の id（UUID）、前後の空白を除いて 10〜500 字の理由、確認の語 `RESET_MFA` だけを受ける（`mfa/reset/route.ts`）
- 認可の直後に、管理者の id ごと 10 回 / 10 分で数え、超えたら 429（SEC-ADMIN-006）
- 自分自身は 400、利用者が無ければ 404、対象の役割が店長・サポーターでなければ 400
- 対象の役割は DB の ACL（`user_roles` の `active` かつ期限内の `roles.code`）で決め、`app_metadata` は使わない。問い合わせの誤りは 500（ADR-0461）
- 2要素の登録を全部消し、1つでも消せなければ 500（失効に進まない）
- 全部消せたら、対象の自前と Auth の session を全部失効させる。失敗は 500 で、消した要素は戻さない
- どの結果も送り元の IP とブラウザの情報付きで監査に残す。理由の文・対象のメール・誤りの文は残さず、理由は長さ（`reason_length`）とハッシュ（`reason_sha256`）だけ。形の誤りは UUID の形の利用者の id だけ、自分自身・対象なし・特権でないは理由の長さとハッシュ、一覧の誤り・消せない時・失効の誤りは理由の長さとハッシュ・対象の役割に加えて、全部の数・消せなかった要素の id・消した数のうち該当する物、成功は理由の長さとハッシュ・対象の役割・消した数

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 確認の語と理由を求めない | 取り違えた id で特権の利用者の2要素を消しても、後から理由を確かめられない（推定） |
| 自分自身のリセットも許す | 乗っ取った人が自分の2要素を外せる（推定） |
| 対象の役割を `app_metadata` で決める（2026-10-26 までの形） | 権限を外された後も `app_metadata` が残り、取り違える。`hybrid-rbac.md` は重要な操作では ACL を見るとし、SEC-ADMIN-014 も ACL を求める（TM-ADMIN-11）。2026-10-26 に ACL に替えた（ADR-0461） |

#### 結果

- 良くなること: 誤った操作を減らし、誰が何の理由で消したかを監査で追える
- 悪くなること: 理由の全文は後から読めない（長さとハッシュだけ）。店長が別の店長の2要素も消せる。本人への知らせは無い（ユーザーの決め待ち。TM-ADMIN-37・40）
- 見直す条件: 2要素のリセットの画面を作る時（今は呼ぶ画面が無い）、店長どうしのリセットを止める時、本人へ知らせる時
