# ADR-0452 監査ログの読み出しは安全な列だけを、新しい順に 100 件返す

> 状態: 推定 | 確認日: 2026-10-24 | 対象: `src/app/api/admin/audit-logs/route.ts` | 基準コミット: `4facf63b`

## 概要

監査ログの窓口は、id・時刻・操作・操作した人の id・対象・対象の id・結果・詳しい文の8つの列だけを、新しい順に 100 件まで返す。操作した人のメール・IP・ブラウザの情報・付帯の情報（metadata）は返さない。

## 範囲と根拠

| 項目 | 内容 |
| --- | --- |
| 範囲 | `scripts/trace/scope.json` の ADMIN |
| 対応する ID | DRV-ADMIN-005、SEC-ADMIN-011。FREQ-508-REQ-01 は読む権限だけを決め、返す列と件数は決めていないので上位にしない（DRV-ADMIN-005 の根拠） |
| 対象のコード | `src/app/api/admin/audit-logs/route.ts` |
| 関連文書 | `docs/05_Quality/reviews/code/2026-04-18-contact-review.md`、`docs/03_BasicDesign/api/api-spec.md` |
| 要件の文書 | `docs/02_Requirements/areas/admin.md` |
| 調べた時点 | 2026-10-24 の作業ツリー（コードは読んだだけで、動かしての確かめはしていない） |

## 判断

### ADR-0452 監査ログの読み出しは安全な列だけを、新しい順に 100 件返す

| 属性 | 値 |
| --- | --- |
| 上位 | DRV-ADMIN-005、SEC-ADMIN-011 |
| 根拠 | 監査ログには、問い合わせ由来の個人情報や操作した人のメール・IP が入りうる。読み出しで全部の列を返すと、窓口がそのまま個人情報の漏れ道になる（2026-04-18 の問い合わせのレビューの指摘）。読む人を店長に絞っても（ADR-0453）、要らない列は出さない |
| 状態 | 推定 |
| 出どころ | `docs/05_Quality/reviews/code/2026-04-18-contact-review.md`、git `77def926`（2026-04-29。全部の列の読み出しを安全な列の一覧に替えた） |

#### 背景

- 前の窓口は監査ログを全部の列で返していた（`2026-04-18-contact-review.md`）
- 問い合わせの処理が、名前や本文を監査ログの付帯の情報に入れていた

#### 決定

- 返す列を8つに決めた一覧で持ち、読み出しはその列だけを選ぶ（`audit-logs/route.ts`）
- 並びは作った時刻の新しい順、件数は 100 件まで。ページ送りは持たない

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 全部の列を返す（前の形） | 問い合わせ由来の個人情報と、操作した人のメール・IP・ブラウザの情報が出る（`2026-04-18-contact-review.md`） |
| 操作した人のメールも返す（`api-spec.md` の書き方） | 今のコードは返さない。どちらが正しいかは決めていない（TM-ADMIN-12） |

#### 結果

- 良くなること: 窓口から個人情報の列が出ない
- 悪くなること: 「詳しい文」の列は返すので、そこに書かれた誤りの文（例 利用者の作成の失敗で Supabase の誤りの文をそのまま書く、`src/app/api/admin/create-user/route.ts`）は出る（SEC-ADMIN-008）。101 件目より古い行は窓口から読めない
- 見直す条件: 監査ログを読む画面を作る時（FREQ-508-AC-01。今は呼ぶ画面が無い）

## 未確認事項
