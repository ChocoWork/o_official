# ADR-0456 管理の返信は保存を先にし、メールが送れなくても保存を取り消さない

> 状態: 推定 | 確認日: 2026-10-24 | 対象: `src/app/api/admin/contact/[id]/reply/route.ts` | 基準コミット: `4facf63b`

## 概要

管理の返信は、店の返信をやり取りの表に保存してから、お客様へメールを送る。メールが失敗しても保存は残し、応答の `mailSent` と監査の結果で送れなかったことを知らせる。

## 判断

### ADR-0456 管理の返信は保存を先にし、メールが送れなくても保存を取り消さない

| 属性 | 値 |
| --- | --- |
| 上位 | DRV-ADMIN-006、FREQ-25-REQ-01 |
| 根拠 | 店の答えはスレッドの記録として残す方が大事で、メールの送り手の一時の失敗で記録を失いたくない。スレッドは会員のページからも読めるので、メールが届かなくても答えは残る（推定。判断の記録は無い） |
| 状態 | 推定 |
| 出どころ | 実装から推定（`src/app/api/admin/contact/[id]/reply/route.ts` の「Reply is saved」の警告）、`docs/03_BasicDesign/api/api-spec.md` |

#### 背景

- FREQ-25-AC-01 は「メールが送られ、スレッドに出る」だけを決め、片方だけが失敗した時の扱いを決めていない
- メールを送る処理と DB への保存は、1つの取引にまとめられない

#### 決定

1. 問い合わせが無ければ 404（`reply/route.ts`）
2. 店の返信を保存する。失敗すれば 500 で止める
3. 問い合わせの状態を answered にし、最後のやり取りの時刻を直す
4. 送り手の住所の設定があればメールを送り、失敗しても保存を戻さない
5. 監査に結果を残し、201 と `mailSent` を返す

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| メールを先に送り、送れた時だけ保存する | 保存の失敗で、届いたメールがスレッドに残らない（推定） |
| メールが失敗したら保存を消して誤りを返す | 店の答えの記録が消え、もう一度書く手間が出る（推定） |

#### 結果

- 良くなること: 店の答えは必ず残り、送れなかったことは応答と監査で分かる
- 悪くなること: 状態の更新（3）の誤りは見ない。送り手の住所の設定が無い時は、メールを送らないのに `mailSent` が真、監査が reply_sent になる（`reply/route.ts`）。この判断は SEC-ADMIN-021 の上位にしない（SEC-ADMIN-021 と SEC-ADMIN-021-AC-02 を参照。TM-ADMIN-07）
- 見直す条件: メールを送り直す仕組み（送る予定の表など）を足す時
