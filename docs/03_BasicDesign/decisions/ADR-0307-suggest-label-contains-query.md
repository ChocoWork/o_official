# ADR-0307 サジェストは、ラベルに入力語を含む候補だけを出す

> 状態: 現行 | 確認日: 2026-10-24 | 対象: `src/features/search/services/search.service.ts` | 基準コミット: `4e84d5c5`

## 概要

入力中の候補は、商品の名前・ルックのテーマ・ニュースの題（ラベル）に入力語を含む物だけにする。説明・本文・カテゴリだけに当たった物は候補に出さない。

## 判断

### ADR-0307 サジェストは、ラベルに入力語を含む候補だけを出す

| 属性 | 値 |
| --- | --- |
| 上位 | FREQ-190-REQ-03 |
| 根拠 | 説明や本文だけに当たった候補は、ラベルに入力語が現れず一致の強調も当たらないので、なぜその候補が出たのか利用者が分からないため（FREQ-190。WAI-ARIA の combobox と Baymard のオートコンプリートの指針に沿う改善） |
| 状態 | 現行 |
| 出どころ | `docs/02_Requirements/requirements.md`（FREQ-190）、`src/features/search/services/search.service.ts` の注 |

#### 背景

候補は検索と同じ3つの DB の関数から作るので、関数が説明や本文の一致で返した行も、そのままでは候補になっていた。

#### 決定

- 正規化したラベルが正規化した入力語を含むかを `labelContainsQuery` で見る（`search.service.ts`）
- 点が 0 より大きく、ラベルに語を含む行だけを候補にする

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 説明・本文・カテゴリだけの一致も候補に出す | ラベルで一致を示せず、候補の理由が分からない（FREQ-190-REQ-03） |

#### 結果

- 良くなること: 候補のラベルの中で、入力語の部分を必ず強調できる
- 悪くなること: 関数は1種別8件を返してからアプリで絞るので、説明だけに当たる行が多いと、ラベルに語を含む行があっても候補が少なくなる（`search.service.ts`、推定）
- 残ること: 候補の取り出しが失敗しても記録に残さず、候補なしと同じになる（DRV-SEARCH-003）
