# ADR-0408 /api/auth/me は認可と同じ根拠で答え、失効を確かめられない時は未ログインにせず 503 を返す

> 状態: 現行 | 確認日: 2026-10-24 | 対象: `src/app/api/auth/me/route.ts`、`src/lib/auth/authenticate.ts`・`src/contexts/LoginContext.tsx`（範囲外の共有部品） | 基準コミット: `4facf63b`

## 概要

`/api/auth/me` は、管理の認可と同じ確かめ（JWT の検証とセッションの生存の確認）で答え、役割は JWT の `app_metadata`、TOTP の済みは `aal2` から読む。セッションの生存を確かめられない時は、未ログインとは答えず、503 と Retry-After 30 秒を返し、画面に前の状態を保たせる。応答は保存させない。

## 判断

### ADR-0408 /api/auth/me は認可と同じ根拠で答え、失効を確かめられない時は未ログインにせず 503 を返す

| 属性 | 値 |
| --- | --- |
| 上位 | DRV-AUTH-007、FREQ-324-REQ-03（範囲外） |
| 根拠 | 確かめられない時に未ログインと答えると、DB の一時の障害だけで全部の利用者の画面がログアウトの状態に落ち、更新の呼び出しが殺到して障害を大きくする（FREQ-324、`me/route.ts`、`8623a554`）。認可と違う根拠で答えると、画面は管理の入口を出すのに API は断る食い違いが起きる（`me/route.ts`） |
| 状態 | 現行 |
| 出どころ | `docs/02_Requirements/requirements.md`（FREQ-324 の行）、git `8623a554` のコミットの文 |

#### 背景

- 以前はセッションの生存の確認の DB の関数が落ちると「失効した」に丸め、`/api/auth/me` は未ログイン、管理の API は 401 を返していた。画面は 401 を「トークンが古い」と読んで更新を呼ぶ（`8623a554`）
- 共有の認証の部品は、生存の確認を「生きている」「失効した」「確かめられない」の3つで返すようになった（FREQ-324-REQ-01（範囲外））

#### 決定

- 認証は共有の部品で確かめる（`me/route.ts`）。確かめられない時は、未ログインの印に理由を添えて 503 と Retry-After 30 秒を返す。失効・未ログインは 200 で未ログイン
- 役割は JWT の `app_metadata` から読み、知らない値は一般の会員にする。TOTP の済みは `aal2` かで決める（`me/route.ts`）
- 応答はどの分岐でも保存させず、参照元を送らない。分岐ごとに書くと増えた分岐だけ抜けるので、組み立てを1つにする（`me/route.ts`）
- 画面（共有の `LoginContext`）は 503 の時に今の状態を保つ（`8623a554`）

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 確かめられない時は未ログインと答える（前の形） | DB の一時の障害で全部の利用者が画面の上でログアウトする（FREQ-324-REQ-03（範囲外）） |
| 401 を返す | 画面が更新を呼び、障害の間に更新が殺到する（`8623a554`） |
| 役割を DB の ACL から読む | 画面の出し分けは表示だけで、管理の操作は管理の認可が DB の ACL で別に断る（SEC-AUTH-028。理由の記録は ADR-0409 の MFA の窓口の物） |

#### 結果

- 良くなること: DB の一時の障害でも画面がログアウトに落ちない。画面の表示と API の認可が同じ根拠になる
- 悪くなること: 役割は JWT の寿命の間（最大1時間）古いままでありうる。画面の出し分けだけなので、権限は増えない
- 試験: 503 の分岐の結合テストは無い
- 見直す条件: 画面の出し分けを DB の ACL に合わせる時、セッションの生存の確認の形を変える時
