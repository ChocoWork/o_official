# ADR-0314 ホームのプレビューは検索語を説明の文に埋めず「検索した語」の枠に出す（案）

> 状態: 推定（案。ユーザーが画面の写真で確かめるまで「現行」にしない。検査が受ける状態の字は「推定」だけなので、案であることは題と本文で示す） | 確認日: 2026-10-26 | 対象: `src/features/search/components/SearchHomePreview.tsx` | 基準コミット: `413d8b36`

## 概要

ホームの `/?q=` のプレビューは、説明の文を固定の「入力した語に関連する結果をホーム上で即時プレビューしています。」にし、URL の語は説明の文の外の「検索した語」の枠（`<dl data-testid="search-preview-term">` の `<dt>検索した語</dt><dd>語</dd>`）に文字として出す。文言と枠の見た目は案で、ユーザーが画面の写真を見て確かめるまで確定しない。

## 判断

### ADR-0314 ホームのプレビューは検索語を説明の文に埋めず「検索した語」の枠に出す（案）

| 属性 | 値 |
| --- | --- |
| 上位 | SEC-SEARCH-021 |
| 根拠 | `/?q=` のリンクで攻撃者の選んだ文を、ホームの店の説明の文の一部として出せた（「本日休業のお知らせ」に関連する結果を…）ため、偽の知らせとして読まれる。ユーザーが「直す」と決めた（2026-10-26、Q19）。語は検索の確認として見せたいので消さず、語だと分かる枠に分ける |
| 状態 | 推定 |
| 出どころ | `.superpowers/sdd/2026-10-25-security-gap-fixes/wave1c-decisions.md`、`design-final.md`（SEC-SEARCH-021） |

#### 背景

- 直す前は「「{語}」に関連する結果をホーム上で即時プレビューしています。」と語を鉤括弧で文に埋めていた。窓口が 400 を返す100字を超える語では区画ごと出ないので、出せる文は100字まで
- React は字を逃がすのでスクリプトは動かない（THR-SEARCH-013）。問題は文として読まれること
- 同じ部品は取り出しの失敗で `Error`（stack つき）を `console.error` に渡していた（SEC-HOME-015）

#### 決定

- 説明の文は固定にする。`<p>` に語を入れない
- 語は説明の文の外の `<dl data-testid="search-preview-term">` に出す。`<dt>` は「検索した語」、`<dd>` は語（文字として出す。`min-w-0 break-words` で長い語を折り返す）
- 区画は結果が返った時だけ出る今の動きのまま。0件でも固定の文と枠は出る
- 枠の色・文字の大きさは既存の変数（`--lk-size-md`）と既存の枠線の色に合わせ、新しい色・影・動きを足さない
- 失敗の記録は固定の文字 `Failed to fetch home search preview` だけにする（`Error` を渡さない）
- 文言と枠の見た目は案。E2E（`SEC-SEARCH-021-AC-02`）が 3 つの幅で保存する画面の写真をユーザーが見て確かめるまで、この ADR と要件は「推定」（案）のままにする

#### 退けた案

| 案 | 退けた理由 |
| --- | --- |
| 語を完全に消す | 何を検索したかが画面から分からなくなる。ユーザーは別の枠に出すと決めた |
| 語を入力欄に出す | ホームのプレビューに入力欄は無い。部品を足すことになり、決定の範囲を超える |
| 語を今のまま文に埋めて受け入れる危険とする | 偽の知らせを店の文として出せる。ユーザーが直すと決めた |

#### 結果

- 良くなること: 攻撃者の選んだ文が店の説明の文の一部にならない。枠は「検索した語」と名乗るので、読む人は語として受け取る
- 悪くなること: 見た目が少し変わる（区画の見出しの下に枠が1つ増える）。枠の中の語は攻撃者が選べる（ただし店の文としては読まれない）
- 検索のページの0件の見出し「「{語}」の検索結果はありません」は FR-SEARCH-004 が求めるので、この決定の範囲外
