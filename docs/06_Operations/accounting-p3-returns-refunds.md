## 概要

計画3は、返品と返金を帳簿に入れる。出荷前の返金は前受金から減らし、出荷後の返品は「店に届いた日」に売上値引・返品として立て、お金が動いた日（返金した日・振込の日）に未払金を消す。カード会社からの支払いの取り消し（dispute）の確定は、すでに返した分・返す約束の分を二重に費用にしないように相殺する。仕訳にできない出来事は捨てず、理由つきで「計上待ち」に残す（計画2と同じ）。

この文書は、運用する人が「返金や返品の記録が何を残すか」「取り消された返金をどう扱うか」「振込で返した時どう記録するか」「判断待ちの注文で何が止まるか」「カード会社の取り消しが確定した時の相殺をどう読むか」を引くための手引き。仕訳の流れの詳細は [計上係のシーケンス](../04_DetailDesign/sequence/accounting-posting.md)、移行の台帳は [DB 移行](db-migrations.md)の計画3の節、計上待ちの全般は[計画2の運用](accounting-p2-posting-stripe.md)。

## 1. 返金・返品の事実を残す仕組み

返金を始める関数・結果を書く関数・返品の受け取りと額を決める関数は、お金の動きを書くのと同じ取引の中で「事実」を残す。計上係は、この事実と Stripe の残高の取引だけから仕訳を作る（ほかの返金の残高は読まない）ので、入る順が入れ替わっても同じ仕訳になる。

| 事実の表 | 何を残すか | 誰が書くか |
| --- | --- | --- |
| `accounting_refund_events` | 返金の状態の履歴（要求・受付・成功・失敗・取り消し・やめた・返すつもり・error・結び）。1状態に1行 | 返金を始める関数・結果を書く関数・error を書く関数・取り消しの区分の関数 |
| `accounting_refund_facts` | 返金の額の事実（出荷前の額・出荷後の額・送料・手数料・返品・交換の出来事）。始める時に1回 | 返金を始める関数・外で返した返金を記録する関数 |
| `accounting_refund_transfer_adjusts`・`accounting_unit_price_adjusts` | 発送前の取り消しで残る着の値段の直し（出荷済みの着／まだの着） | 発送前の取り消しの返金 |
| `accounting_return_facts` | 返品の届いた時の額と手数料、額の決定（返金を始める・0円で終える） | 返品の受け取りの関数・額を決めて返金の関数 |
| `order_return_arrival_corrections` | 届いた日の直し（前後の日・理由・人） | 届いた日を直す関数 |

作り直した関数・表の一覧は[DB 移行](db-migrations.md)と[ER 図](../03_BasicDesign/data/er.md)。

**品を送り返さない返品（返送不要。返品の `return_method` が `not_required`）**（S26。P3-F1。設計 5-e、計画の未確認事項 14）

- 品が戻らないので、**届いた日の仕訳も額の決定の仕訳も作らない**（受け取りを記録しても返品の事実を残さない）。受け取りの記録に「届いた日」は付くが、仕訳の日にはならない。
- 返金は、残高の取引の日（返金した日）に「売上値引・返品 4020／Stripe 未収金 1160」の**1本だけ**を入れる。2130 の返品の返金待ちは立たない。返金した日が次の年なら、その年の期間に入る（受け取った年へ寄らない）。
- 引かれる前に失敗した時の借りは、出荷後の返金の借り（2130 `refund_owed_post`。借りの一覧の「出荷後の借り」）に立ち、振込は出荷後（`post_shipment`）で返す。返品の借り（`return`）には出ない。結びも普通の出荷後の借りと同じく使える。
- 普通の返品（品を送り返す）はこれまでどおり、届いた日に 4020／2130 を入れ、返金した日に 2130／Stripe 未収金を入れる。

**失敗した時の見方**

- 事実は返金・受け取りと同じ取引で書くので、途中で失敗すると事実も返金の行も残らない（片方だけ残ることは無い）。画面には route の固定の文が出る。
- 事実はあるのに仕訳が入らない時は、計上待ちに理由が出る。返金・返品に関する理由は次のとおり。人が手で閉じてよいのは `before_cutover` と `no_revenue` だけ（計画2と同じ）。`order_not_postable` は手で入れた仕訳と結んで閉じる（6節の④）。

| 理由 | 何が起きているか | 次にすること |
| --- | --- | --- |
| `refund_prior_unposted` | 返金の仕訳の前に要る仕訳（返品の届いた日の仕訳・元の仕訳・戻りの取引）がまだ無い（詳細 `why`: `return_prior`・`original`・`failure_txn_missing`） | 前の仕訳が入る・戻りの取引が同期されると自動で計上。手では閉じられない |
| `refund_cancel_undecided` | Stripe が取り消した返金の区分が未選択 | 2節。区分を選ぶまで計上待ちに残る |
| `amount_mismatch`（詳細 `mismatch`: `refund_amount`・`allocation_overflow`・`unit_value_left`） | 返金の額が残高の取引と合わない／割り当てが着の値打ちを超える | 取引が同期し直されると再確認。直らなければ元の記録を確かめる（返金は落ちず、ここに止まる） |
| `order_not_postable`（詳細 `reason`: `shipping`・`units_*` ほか。`dispute_lost`・`return_closed_after_lost` は S27 の後は新しく作られない） | 送料つきの返金は自動で仕訳にしない。確定した取り消しの後の0円の終わり（`dispute_lost`）は、S27 から返品の計上係が自動で入れる（14節）。S27 の前に作った開いた `dispute_lost` の行は、次の流しで自動で入る・待ちの理由に変わる・`no_revenue` で閉じる | `dispute_lost`・`return_closed_after_lost` は結ばない（自動。S27 の前に作った開いた行も計上係が入れる）。`shipping`・`units_*` は手で仕訳を入れて結ぶ（3節の⑤）。理由ごとの文は画面に出る |

## 2. 取り消された返金の扱い

Stripe が返金を取り消した時（`canceled`）、帳簿はどちらか分からないので、**店が区分を選ぶまで計上待ち（`refund_cancel_undecided`）に残す**。区分は計上待ちのタブの行から選ぶ（権限 `admin.accounting.entries.correct`。理由は必須）。選ぶと次の計上で仕訳になる。

| 区分 | 選ぶ時 | 選んだ後の仕訳 |
| --- | --- | --- |
| 店が返金をやめた（`abandoned`） | お客様に返さないと店が決めた | 引かれた後なら、戻りの取引の日に元の仕訳の取り消しだけ。引かれる前なら仕訳を作らない。発送前の取り消しの返金なら、その着がまた送れるようになり、前受金は出荷まで残る（止めた日に売上の仕訳は入らない。出来事の後に出荷された残る着に直しがあれば、その分だけ区分の仕訳に 2150／4010 が入る） |
| 返すつもりのまま返せなかった（`owed`） | 別の方法で返す | 失敗と同じ借りを立てる（引かれた後は「Stripe 未収金／返金の未払い」、引かれる前の出荷前は「前受金／返金の未払い」、引かれる前の返品は仕訳を作らず届いた日の未払金が残る）。借りは4節の振込かやり直しの結びで消す |

- 2回目の選びは前の結果（同じ内容）、違う内容は 409 `ACCOUNTING_REFUND_CANCEL_DECIDED`。取り消されていない返金は 409 `ACCOUNTING_REFUND_NOT_CANCELED`。
- Stripe に届いていない `error` の返金は、発送前の取り消しの戻しを断る（DB は `UNIT_CANCEL_REVERT_REFUSED`、DETAIL `ubrr_status`。route は DETAIL を返さず、409 `UNIT_CANCEL_REVERT_STRIPE_RETRY` と「Stripe への返金をやり直してください。」を返す）。`error` の返金は、返金をやり直す道しか無い。
- 引かれて戻された（`succeeded` の行が無いまま Stripe が取り消した）返金は、戻りの取引が無い間だけ `failure_txn_missing` で待つ。

## 3. 振込で返した時の記録の手順

返金に失敗した・やめられなかった借り（2130 の返金の未払い、返品の返金待ち）は、**振込で返した事実を記録するか、やり直しの返金で結ぶ**ことでだけ消える。記録は Stripe 精算のタブの「返金の借りと振込の記録」（権限 `admin.finance.manage`）。

### 手順

1. 借りが残る返金の一覧から行を選ぶ。注文・借りの種類（`origin`）・額が入る。
2. 借りの種類を選ぶ。`pre_shipment`（出荷前の借り）、`post_shipment`（出荷後の借り）、`return`（返品の借り）。
3. 額（1円以上、借りの残高まで）、振込の日（今日の日本の日付まで。確定した取り消しがある注文は確定の日より後。新しい帳簿の始まりの日より前は、画面が注意を出す）、**銀行の取引の番号**（英数字・`_`・`-` の1〜100文字）、メモ（任意）を入れる。
4. 記録すると、振込の日に「返金の未払い／普通預金」（返品の借りは 2130 が減る）の仕訳が入る。

- **同じ銀行の取引の番号・同じ種類（`origin`）の2回目は何も足さない**（`created:false`。監査の結果は `duplicate_bank_txn`）。額が違えば `DEDUPE_CONTENT_MISMATCH`。同じ要求番号の再送は最初と同じ結果。
- 借りの残高を超える額、未来の日、額0、権限なしは断る（409 `ACCOUNTING_EVENT_NOT_POSTABLE` ほか）。
- **種類 `return` は、同じ注文に Stripe で処理中（`awaiting_response`・`pending`）の返品の返金がある間は断る**（409 `ACCOUNTING_REFUND_IN_FLIGHT`）。処理中の返金が成功すると、振込と合わせてお客様に二重に返してしまうため（P3-T11i）。結果が出てから記録する。同じ銀行の取引の番号の再送は対象外。
- **`error` の返金は処理中と数えない**（`error` は Stripe に返金が無いことを意味し、数えると払えなくなるため。P3-T11k）。その返金を後でやり直して成功し、先に振込を記録していると、2130 の返金の残高が負になる。**前受金の異常の一覧**（計上待ちのタブの下の「前受金の確認」。理由 `return_refund_negative_balance`「返品の返金待ちがマイナスです」）がその注文を出す（S26。P3-F3）ので、そこで見つけて、二重に返した分を確かめる。この印は**今の残高の印**で、残高が0以上に戻ると消える（履歴の印ではない）。ただし手で入れる仕訳に注文と補助科目の入力が無い間は、手では戻せないので、見つけたら残ったままになる（オーナーの決定待ち。未確認事項 2）。受注高の照らし合わせそのものは注文ごとの一覧を持たず、2130 の返品の返金待ちは数えないので、そこには出ない。`error` の返金をやり直す前に、同じ注文の振込を記録していないか確かめるのが先。
- 借りの一覧の「返品の借り」（`owed_return`）の額は、注文の 2130 返品の返金の残高から、同じ注文の処理中の返品の返金を引き、その返金自身の出荷後の額を超えない額（0を下回らない）。**送料の部分は含めない**。送料つきの返金は計上待ち（`order_not_postable`）に止まり、送料の分は手で返して記録する（P3-T11l）。

### やり直しの結び

借りの返金に対して、成功したやり直しの返金（同じ注文）で結ぶ道もある（権限 `admin.accounting.entries.correct`）。借りの行の「やり直しと結ぶ」から、**結べる返金の候補**だけが並ぶ（候補の読み: `GET refund-settlements/candidates`）。

- 候補は、同じ注文で、成功の行があり、まだどの結びにも使われていない返金。借りと同じ出来事の返金（`sameEvent`）が先頭、次に成功の日（その返金の残高の取引の日）、返金の番号の順。
- 候補に出ても、結ぶ時に断られることがある（例: 結びの仕訳の日の期間が無い）。理由の文が出る。
- 発送前の取り消しの出来事の借りには候補が無い。振込の記録へ進む（出荷前の借りは返し直さず、振込で返す）。
- **普通の返品の返金の借り（届いた日の返品の返金待ち 2130 `return_refund`。借りの一覧の「返品の借り」）は結べない**（S26。P3-F2）。結びの仕訳は出荷後の借り（`refund_owed_post`）を減らすので、同じ注文にほかの返金の出荷後の借りがあると、その借りを間違って消してしまう。DB は `ACCOUNTING_ARGUMENT_INVALID`（SQLSTATE 22023、DETAIL `settle_plain_return`）で断り、route は 400「入力を確かめてください。」を返す（DETAIL は返さない）。候補の読みもその借りには空を返し、画面は結ぶ操作を出さない。**払い手の側も同じ**: 成功した普通の返品の返金（2130 `return_refund` から払った返金）を、ほかの返金の出荷後の借りを消す払い手にすることも断る（DETAIL `settle_plain_return_payer`。結びの仕訳が4020を戻すのに、その返金は4020に入っておらず、お金の裏付けが無いため。P3-F8）。結びの候補にも出さない。返品の借りは3節の振込（`return`）で返す。返送不要の返品（1節の「品を送り返さない返品」）の借りは出荷後の借りなので、これまでどおり結べる。
- 結びで戻る額は、元の返金の借りのうち結んでいない額と、やり直しの返金の額の小さい方。2回目は何も足さない。

### 手で入れた仕訳と結んで閉じる（計上待ち `order_not_postable`）

自動の仕訳にできない行（送料つきの返金など `shipping`・`units_*`。確定の後の0円の終わり `dispute_lost` と、0円の終わりが先に入っていた確定 `return_closed_after_lost` は S27 から計上係が自動で入れるので結ばない）は、手で仕訳を入れてから結んで閉じる。計上待ちの行の「手で入れた仕訳と結んで閉じる」から、**取り消されていない手入力の仕訳**を選び、メモ（必須）を書く。

**警告**: S27 の前に作った開いた `dispute_lost`・`return_closed_after_lost` の行に、手の仕訳を結ばない。S24 の結ぶ関数はこの行を今も受け付けるが、結ぶと行が閉じて計上係が C を入れなくなる。例(d)なら 1470 `dispute_pending` が借 4,000 のまま残る。

- 結べる仕訳は種類 `manual_entry` で、取り消しの仕訳でなく、取り消されていないもの。待ちに注文がある時、仕訳に注文の付いた行があれば**同じ注文の行が1つ以上**あること。どの行にも注文が付かない仕訳（経費の入力の道の仕訳）は結べる（P3-T11b）。だから結ぶ人が、手入力の中身（額・科目）に責任を持つ。断られた時の理由は `link_not_found`・`link_not_manual`・`link_reversed`・`link_other_order`。
- 1つの仕訳で複数の待ちを閉じてよい。同じ要求番号・同じ内容の再送は前の結果。閉じた人・メモ・仕訳の番号が計上待ちの行に残る。
- 注意: アプリには、注文の付いた手入力の仕訳を作る入力が無い。2130・1470 の補助科目を選べる入力も無い。dispute の確定の分け方など、補助科目の仕訳が要る時は、オーナーが入力の道を決めてから使う（Task 14 の報告の未決事項）。

## 4. 判断待ちの注文の返金・出荷が止まること

カード会社の取り消し（dispute）が判断待ち（`get_order_dispute_holds` が返す注文。引かれて同期が済み、まだ確定も取り下げもされていない）の注文は、次を止める。止まった時の画面の文は、判断待ちの案内が1行出て、送れない。

| 止まるもの | どう止まるか |
| --- | --- |
| 管理者の返金・支払い済みの注文のキャンセル・返品の返金・受け取りの今すぐ返金 | DB の返金を始める関数が `ACCOUNTING_DISPUTE_HOLD`（SQLSTATE 55000）で断り、route が 409 `DISPUTE_HOLD` と `orderIds` を返す。返金の行・履歴・事実・割り当て・Stripe の呼び出しは何も残らない |
| 発送票の確定 | route の事前の読みと、DB の関数の両方で断る（409 `DISPUTE_HOLD`）。票は下書きのまま。複数の注文を束ねた票は、1つでも判断待ちなら全体を断る。確定済みの票の再送は、後から判断待ちになっても前の結果を返す（`replayed`） |

- **止める条件**: 注文に、判断待ちの dispute がある（`get_order_dispute_holds`）こと。
- **止まらないもの**: ①自動の返金（支払いの異常で返す `auto_*`）、②Stripe の管理画面で店が返した返金の記録（`record_external_order_refund`。自動の返金ではなく、記録するだけでお金を動かす操作ではない）、③前の注文から差し引いた分を戻す返金（`unit_hold_release`。後の注文の受け取りが、前の注文の差し引いた分を返す。2026-11-10 にオーナー承認。後の注文が判断待ちでなければ、前の注文が判断待ちの間も通る）。warning 系の問い合わせは止めない。返品を0円で終える操作（返金の記録を作らない）も止めない。
- **解けるのは**、dispute が確定（lost）または取り下げ（won）になった後。確定・取り下げの後は返金も発送も通る。
- 画面の印（`disputeHold`）は案内で、**読めなかった時は偽にする**（止めるのは DB なので、偽でも送ると409で止まるだけ）。発送票の事前の読みは逆で、**読めなかった時は固定の500で確定しない**（計画2から続く止め方。返金の画面は DB の止めと二重なので、読み取りの失敗で画面を使えなくしない。Task 10 の判断）。失敗は `[refund.dispute-hold]` として値を出さずにログに残る。
- 判断待ちの前に始まった保留の返金が、判断待ちの間に失敗した時も、戻りの取引を確かめ、同じ返金を二重に作らない。

## 5. カード会社の取り消しが確定した時の相殺の見方

確定（C）の時、その注文の次の2つを二重に費用にしない。

| 記号 | 意味 | どこへ |
| --- | --- | --- |
| R | 返品の返金待ち（2130 `return_refund`。確定の日以前の残高） | 取り消しの額 S の範囲（R と S の小さい方）だけ「2130／1470」で消す（メモ `offset_pay:<額>`） |
| Z | 返金済みと重なる分（出荷後の返金の実額。確定の日以前の返金の仕訳から、引かれた後の失敗で戻った分と別の取り消しで使った分を引く） | S から R の分を引いた残りの範囲（Z と残りの小さい方）だけ、1470 の補助 `dispute_refund_overlap_review`（画面の語「分けて調べる」）へ移す（メモ `offset_review:<額>`） |
| 残り | 取り消しの額 S から R の分と Z の分を引いた額 | 原因の科目の費用（計画2のとおり） |

- 例: 返品の返金待ち16,875円・取り消し30,000円なら、2130 を16,875円消し、費用は13,125円。返金済み16,875円なら、16,875円が「分けて調べる」の補助に入り、費用は13,125円。
- **待つ場合**: 確定の日までに作った返金の結果が出ていない間（状態が `requested`・`accepted`・`error`、または仕訳が入っていない）は `dispute_refund_overlap`、確定の日以前の届いた日・額の決定の仕訳が入っていない間は `dispute_return_refund_pending` で待つ（詳細 `why`）。手では閉じられない。仕訳が入ると自動で計上される。注文の無い取り消しは待たず、相殺しない。
- **遅れた取り下げ（L）**は、費用の科目（振り替えた科目）の残高 → 「分けて調べる」の補助の残高 → 返金待ち（2130）の順に戻す。
- **確定の後の操作の制限**: 確定の日以前の届いた日の受け取り、確定の日をまたぐ届いた日の直し、確定の日以前の振込の日は断る（`RETURN_ARRIVAL_DATE_INVALID`・振込の日の検査）。確定の仕訳が入った後に、確定の日以降に返品を0円で終えると、その終わりは仕訳にならず `order_not_postable`（`dispute_lost`）で手で入れる待ちになる。0円の終わりが先に確定の日より後の日で入っていると、確定が `order_not_postable`（`return_closed_after_lost`）で待つ。
- **分けて調べる補助の読み方（M11）**: 「分けて調べる」は**補助科目の名前としてだけ**画面に出る。専用の画面の欄は無い（文言 `disputeOffsetReview` は仕訳の説明の語としてあるが、どの画面も描かない）。見る時は、仕訳帳で勘定 1470 の補助 `dispute_refund_overlap_review` の行を探し、注文と取り消しの番号で、その確定の相殺（メモの `offset_review:`）の行を読む。残高の0への戻りは、遅れた取り下げの時に起きる。試験もこの補助の残高だけで確かめている。
- **ある確定が使った分は、別の確定が使えない**（補助の現在の残高を Z から引く）。同じ注文に取り消しが2つある時は、1つ目が使った分を2つ目は除く。既知の穴: `dispute_lost` の手で入れる待ちが開いている間は、別の取り消しの確定が、その待ちが消すはずの 2130 を相殺に使いうる（1つ目が一部だけだった時。未確認事項 4）。

## 6. 届いた日の直し

返品の「届いた日」は、お客様に品が届いた日でなく、**返品の品が店に届いた日**（所得税基本通達51-18。方針 3-1）。既定は受け取りを記録した日で、受け取りの画面で選べる（今日まで。未来は不可）。運送会社の配達日を使う設定（設定のタブ。既定オフ。変えた日と人が残る）は、オンにしても、返品の追跡を登録できるまでは配達日が入らず、届いた日は記録した日（または選んだ日）のまま。オンにする前に注意の文を読む。

- 直す操作は、返品の詳細の「届いた日を直す」（権限 `admin.accounting.entries.correct`、理由必須、版の確認つき）。受け取りの行は変えず、直しの行を足す（版・前後の日・理由・人が残る）。画面の詳細に、直した跡が古い順に出る。
- 直すと、古い日の仕訳の取り消しと、直した日の同じ行の仕訳が入る。直した先の日に期間が無ければ `period_missing` で止まり、元の仕訳は取り消されないまま残る。2回直しても取り消しは1回ずつで、最後の日の仕訳だけが残る。
- **断られる場合**: 未来の日、返品の申し込みより前の日（お店が作った返品は、その注文の最初の出荷の日より前）、**取り消しが確定した注文では、確定の日以前への直しと、確定の日以前だった日を後へ直すこと**（`RETURN_ARRIVAL_DATE_INVALID`。画面は「届いた日を確かめてください。」）。
- 直した人の番号（`actorId`）は、返品の詳細の跡に頭の8文字が出る。名前・メールは返さない。

## 7. 消費税用の返金の一覧の見方と対象外の理由

照合のタブの「消費税用の返金」。期間を月（`YYYY-MM`、最大12か月）で選ぶ。返金した年月日（残高の取引の日、振込なら振込の日）・注文番号・品の内容・税率・返金の額・税額・元の売上の日・対象外の理由が出る。名前・メール・住所は出さない。「消費税法施行令58条の2により7年間保存する」の注記が付く。額は、客へお金が出た日が `+`、戻った日（失敗の戻り・店がやめた取り消し）が `−`。

| 対象外の理由 | 意味 | 外す理由 |
| --- | --- | --- |
| `before_sale` | 出荷前の返金（売上になっていない） | 売上でないので返還の対象でない |
| `sale_unbooked` | 出荷後の分で、その注文の出荷の仕訳がまだ無い | 手で確かめる（安全側で控除に入れない）。人が確かめて入れる |
| `exempt_sale_14_1_6` | 免税の期間の売上の返金 | 元の売上が免税の期間なら「38条の控除の対象外（14-1-6）」として合計から外す（設計 5-j） |
| `after_exit_14_1_7` | 課税の売上で、返金した日の期間が免税の返金／元の売上と返金の期間で事業の形が違う（個人 → 法人。課税事業者でなくなった後・事業をやめた後の返金） | 「対象外（14-1-7）」として外す（設計 5-j） |
| `none` | 元も返金も課税で同じ事業の形 | 合計に入る |

- 理由の順は `before_sale` → `sale_unbooked` → `exempt_sale_14_1_6` → `after_exit_14_1_7` → `none`。分けて送った注文の返金は、返した品の出荷の日で決まる。
- 元の売上の日は、返金の出荷後の明細の品を運んだ出荷の仕訳の最も早い日。つながらない時は、注文の最も早い出荷の仕訳の日。**品ごとの突き合わせで、着ごとではない**（同じ品の別の着が別の日に出た時は、早い日になる）。
- **月の境の法人成り**: 期間は月で選ぶので、法人成りの月は個人と法人が混ざって合計される。行には返金した日と期間の状態が付くので、手で月の中を分ける（Task 14 の報告の既知の制限）。
- 返金の日が期間の外の行・店がやめた成功の取り消しは、戻りの日の `−` の行で出る。

## 8. 返送料・交換の手数料を使いたくなった時の手順

返送料の定額・交換の手数料・交換の送料は、**仕訳の決まりがまだ無い**ので、設定でオフに固定し、DB でも0に止めている（S16の CHECK。0でない値や有効化は SQLSTATE 23514 で断る）。割合の返品手数料は今のまま使える。

使うと決めた時の順番:

1. 先に、設計 5-b（と必要なら 2-c）に**仕訳の決まり**を足す（どの勘定・どの日・免除の時の扱い）。オーナーが読んで確かめる。
2. 返金・返品の仕訳と事実（手数料 F の列）をその決まりに合わせて直す計画を作り、試験を足す。
3. S16 の CHECK 2つ（`acc_p3_fee_lock_settings`・`acc_p3_fee_lock_returns`）を、新しい移行で外す。本番の既存の行は検査していない（`NOT VALID`）ので、外す前に返品の行を確かめる。
4. 設定の画面の入力の無効化と、route の zod の断りを戻す。

決まりを足す前に CHECK だけ外してはいけない。外すと、仕訳にならない手数料が受け取りに入り、返金額と帳簿が食い違う。

## 9. 本番で試しの返金・返品を作らない決まり

本番の DB・本番の Stripe で、試しの返金・返品・取り消しの区分・振込の記録を**作らない**。仕訳・事実・計上待ちは消せず、受け取りの表（届いた日）・事実の表も追記専用なので、試しの行が帳簿に残り続ける。

- 試しは手元の Supabase（`npm run db:start`・`db:reset`）でする。E2E は手元の Supabase にだけ書く（本番を拒む見張りがある）。
- 本番へ当てた後の確かめは、読むだけの問い合わせ（行数・関数の指紋）と、承認を得た画面の読みだけ。
- 事実の表と受け取りの表は、S15 の当たる前提が「0行」であることに注意（当てる前の試しの受け取りが残ると S15 が止まる）。

## 11. Stripe の画面で返し、まだ記録していない返金

Stripe の管理画面で返したが、アプリに記録していない返金（`order_refunds` の行が無い）の残高の取引は、Stripe の残高の照合で **`planned_p3`（計画3で計上する種類）に残り続ける**。返金の係は `order_refunds` の行が無い取引を読まないので、計上待ちの行も作らない（照合の `planned_p3` にだけ残る）。

- Stripe の返金の知らせを受け取る worker（`order-refund-sync`）が、こちらの印の無い返金を記録する関数（`record_external_order_refund`）で記録する。記録されれば取引が注文に結び付き、返金の係が仕訳にして、`planned_p3` から外れる。知らせが届かない・記録が失敗している間は残る。
- 計上待ちの行を人が閉じた（`resolved_by` あり）返金の取引は、`planned_p3` から外れる（S24）。人の操作だけが対象で、自動の解決は含まない。
- 開店前に件数が0であることを確かめる。

## 12. 交換の設計の出来事と仕訳の対応

交換の印の作業の出来事ごとに、返金の事実の `event_kind` と仕訳が決まる。着ごとの値段の直し（d）は、発送前の取り消しの時に記録し、仕訳にするのは出荷前の返金で売上へ寄せる分だけ。

| 出来事 | `event_kind` | 仕訳 |
| --- | --- | --- |
| 発送前の取り消し（1着・複数・交換の品だけ） | `pre_shipment_cancel` | 返金した日に「前受金／Stripe 未収金」。取り消した着に全額の割り当てが入り、その着は出荷の対象から外れる。残る着の値段の直しは、出荷済みなら返金の仕訳で売上へ寄せ（d）、まだなら出荷が今の値段で入る。上限（V_P）を超えた分は 4020／1160 |
| 店が発送前の取り消しをやめた（区分 `abandoned`） | — | 品を送れるように戻し、割り当てが戻る。前受金は送るまで残り、止めた日に売上は入らない。戻せなかった分 s だけ区分の仕訳に 2150 s／4010 s |
| 返品（受け取り）の返金 | `return_receipt` | 届いた日に 4020 G／2130 G と 2130 F／4050 F（G は返す額 ＋ F、F は手数料）、返金した日に 2130／Stripe 未収金。**返送不要の返品は、届いた日の仕訳が無く、返金した日に 4020／Stripe 未収金の1本だけ**（1節） |
| 手元に残る着の値段の直し（セット買いの片方を返す・前の注文から差し引く） | — | 仕訳にしない（記録だけ）。4020 の累計は実際に返した額と手数料の合計になる |
| 前の注文から差し引いた分を返す返金・交換の品の発送前の取り消しの返金 | `holdback_release` | 返品の届いた日・額の決定の仕訳を待たず、返金した日に 4020／1160 の1本。引かれる前に失敗すると 4020／2130（`refund_owed_post`）の借り。手数料 F があれば 4020 F／4050 F を足す |

## 14. 確定の後の0円の終わり（S27。返品の計上係が自動で入れる）

> 状態: S27 の返品の計上係の分（手元の Supabase で確かめた分。本番には未適用） | 確認日: 2026-11-15

確定 C が入った取り消しの負けた日以降に、返品を0円で終えた（返金なしの決定の）仕訳は、人が手で入れず、返品の計上係が自動で入れる。

- **待ち**（この順。どれも解けると次の流しで自動で入る）: 日の早い物が先（同じ注文に、日の鍵が小さくてまだ入っていない決定がある。切り替えの日より前の `before_cutover` の開いた行は数えない）→ 途中の返金（`dispute_refund_overlap`、詳細 `why` `refund`）→ ほかの返品の返金の額が未決（P_eff = min(P(決定の日)、P(今)′) が 0 より大きい間だけ。D14・D15。返金が失敗して銀行振込で払われた返品のように決定が数えられない返品では待たない。`dispute_return_refund_pending`、`why` `return`）。
- **途中の返金から外す例外**: 同じ返品の後の返金 R が、この決定（と日の鍵がそれより後の決定）を待っているだけで、成功の仕訳がまだ入っていない時は、互いに待たないよう途中の数から外す。
- **入れる額**: P_eff = min(P(決定の日)、P(今)′)。w = min(決めた額 c、max(P_eff、0))。w が正なら w だけ入れる。P_eff が0以下なら入れず `no_revenue` で閉じる（返金の係は、閉じた決定を済みと数えて同じ返品の後の返金を入れる）。
- **入れた後の確かめ**: 入れた後に 2130 が負になる時は `ACCOUNTING_POSTING_BALANCE_NEGATIVE` で巻き戻し、計上待ちに `posting_error` が出る。通常は起きない守り。
- **取り出しの順**: 返金なしの決定を取り出す順は、返品の計上係が `ORDER BY lane, phase`（同じ階の中は作った時刻・返品・番号の順）、取り消しの計上係が `ORDER BY j.phase, j.lane`（S22）で違う。そのため「日の早い物が先」の待ちを返品の計上係の中に持つ。
- **S27 の前に作った開いた `dispute_lost` の行**: S27 を当てた後の返品の計上係の流しを重ねるうちに（1回の流しで取る行は1つの階につき10行まで）、自動で入る・待ちの理由に変わる・`no_revenue` で閉じるのどれかになり、開いたまま残らない。

## 15. 確定の前に0円の終わりが入っていた時（S27。取り消しの計上係が C と直しを自動で入れる）

> 状態: S27 の取り消しの計上係の分（手元の Supabase で確かめた分。本番には未適用） | 確認日: 2026-11-16

確定 C の前に、負けた日より後の日付の返金なしの決定の仕訳（取り消されていない）が入っている注文は、S27 の後は取り消しの計上係が止めず、C と直しを1つのトランザクションで入れる。

- **待ち**（この順。どれも解けると次の流しで自動で入る）: C の前提（引かれた分が全部入っている・負けた時刻以前の取り下げが未計上でない → `dispute_withdrawal_missing`、`accounting_dispute_offset_ready` → `dispute_refund_overlap`・`dispute_return_refund_pending`）→ 途中の返金が1つでもある（`dispute_refund_overlap`、`why` `refund`。負けた日で切らず、外さない）→ D13・D15: C の `pay` が負けた日の R より小さい、または額が未決の返品に負けた日より後に届いた到着がある時で、かつ C の前の 2130 が 0 より大きい時だけ（D14）、額が未決の別の返品（その注文の全部の返品）があれば `dispute_return_refund_pending`（`why` `return`）で待つ → 日の早い物が先（`dispute_return_refund_pending`、`why` `return`。C の鍵の日は最後の0円の終わりの日。鍵が同じか小さい未計上の決定、または鍵の日が小さく、同じ日なら取り消しの番号が小さい別の取り消しの C。済んだ C・仕訳なしや人が結んで閉じた C の行・切り替えの前に負けた取り消しは数えない）。
- **C**: 今の計上係の C の文のまま（印 `dispute_event:<dp>:confirmed:lost`・日は負けた日）。待ちが全部解けた時に、行の組み立てを変えずに入る。
- **直し**: 0円の終わりの日（取り消されたものを除く）を早い順に n = 1, 2, … とし、各 d_n で y_n = max(−B(d_n), 0)。B(d_n) は d_n までの 2130 `return_refund`（C・前の直しを含む。返金の成功は作った日で数える）。y_n > 0 なら 借 4020 y_n／貸 2130 `return_refund` y_n（行に注文・memo `closefix:<n>`・日は d_n・見出しは 0円の終わりと同じ・記録の時刻は入れた時刻）を、印 `dispute_event:closefix:<dp>:<n>` で入れる。印の頭が `dispute_event:<dp>:` の外なので、取り消しごとの残高と遅れた取り下げ L の振り分けは直しを読まない。d_n の期間が無ければ C も直しも入らず、`period_missing` の `detail.entry_date` が d_n になる。
- **最後の直し（D12）**: 最後の d_n だけ y = max(−B(d_n), min(−P(今), C の pay − 前の直しの合計), 0)。最後の0円の終わりの日 d_last より後に作った返金の成功が C の前に入っていて今の 2130 が負でも、C が取りすぎた分（pay まで）は戻す。pay を超える分は隠さず、今の 2130 の負として残り、前受金の異常の一覧（`return_refund_negative_balance`）に出る（エラーにはしない。D16・D17）。
- **D16**: 最後の直しは、C の pay と、0円の終わりが 2130 から取った額（負けた日より後・取り消されていないもの）も超えない。C と関係ない二重払いは隠さず、2130 の負として残り、前受金の異常の一覧（`return_refund_negative_balance`）に出る（エラーにはしない）。
- **既知の限り（D16）**: 取り下げ L の日が0円の終わりの日より前なのに、L が C・直し・0円の終わりの評価より後に入ると、2130 が 10,000 円残り売上の純額が 10,000 円少ない形になる（時間どおりなら 2130 = 0・売上の純額 10,000。お金の合計は同じ）。**この形は異常の一覧に出ない**ので、返金の借りの一覧と銀行振込の上限が、残った 10,000 円を払えるものとして出す。**返品の借りを払う前（銀行振込・やり直しの返金）に、その注文に負けた取り消しがあれば、取り下げ L の日と0円の終わりの日を見比べる**: L の日が0円の終わりの日より前なら、時間どおりの帳簿では 2130 は 0 で払う借りは無い（売上の純額 10,000）。払う前に税理士に確かめる。N7 の鏡（負けた日より後に届いた返品を0円で終え、早く届いた返品を返金する）は、正しい終わりが 2130 = 0・売上の純額 0 で、30通りの順のうち C が最後に入る1通りだけ 2130 = −10,000・売上の純額 10,000 になる（この1通りが既知の限り。異常の一覧に出る）。手の仕訳は注文と 2130 の補助科目を持てないので、どちらも手では直せない。異常の一覧に出た注文は、そのまま残し、税理士に伝える。
- **D17**: 直しは全部、その日までの0円の終わりが 2130 から取った額までに上限がつく。C が覆った返品への2回目の払い（返金や銀行振込）は、C や0円の終わりと入る順によらず、2130 の負として異常の一覧に出る（負けた日より後に届いた返品が0円で終えられている形を除く。その形は N7 の鏡のとおり 2130 = 0・売上の純額 0 が正しい終わりで、二重払いではない）。
- **入れた後の確かめ**: 上限に止められなかった直しで d_n までの 2130 が0未満なら（D17。止められた直しの負は C と関係ない二重払いなので例外にせず、異常の一覧に出す）、全部入れた後に 1470 `dispute_refund_overlap_review` が0未満なら、`ACCOUNTING_POSTING_BALANCE_NEGATIVE` で巻き戻す。
- **注意（N18）**: 負けた日と同じ日に0円で終える前に、その取り消しの確定 C の仕訳が入っているか確かめる。入っていなければ、翌日に終える（負けた日より後の日付なら、待ちと直しが効いて、どの順でも同じ終わりになる）。同じ日に C より先に0円で終えると、同じ注文の別の返品を後で返金した時に、2130 が負（異常の一覧）か review に利益 10,000 円ぶん多く残る形が起きる（設計 14章 N18。例: 返金 16,875 円・取り消し 10,000 円で 10,000 円）。異常の一覧や review の欄を二重払いと見る前に、0円の終わりの日と負けた日を比べる。
- **取り消し（AC-11）は組で**: 自動で入れた C と直し（印 `dispute_event:closefix:<dp>:*`）は別の仕訳で、片方だけ取り消せて、計上係は入れ直さない。C は直しと一緒に取り消す。0円の終わりの仕訳は、その日に入れた直しと一緒に取り消す。例(d)で C だけ取り消すと 2130 が貸 4,000 残り、4,000円の返品の借りの銀行振込が通ってお客様に二重に払うが、異常の一覧には出ない（試験 `FREQ-643-AC-11: C だけを取り消しても（直しは残す）…`、`accounting_p3_pending_auto_posting.integration.test.ts` の 2295 行付近が、この動きを固定している）。
- **S27 の前に作った開いた `return_closed_after_lost` の行**: 取り消しの計上係の流しを重ねるうちに（1回の流しで取る行は1つの階につき10行まで）処理され、`resolved_entry_id` は C の仕訳（直しでなく）になる。人が結んで閉じた行がある時は S27 の前の確かめが移行を止める。

## 運用の注意

- E2E の後に DB 結合を流す時は先に `npm run db:reset`。計画3のコミットする試験（`ACCOUNTING_COMMIT_SUITE=1`）も、単独で流し、前後に `db reset` を挟む。
- 計画3の E2E（`FR-ADMIN-137`〜`140`）は本番ビルド・手元の Supabase で流す。`FR-ADMIN-140` は返品の設定の行を書き換えるので、`isolated-global` で順に流す。
- 返金・返品の試験で「Stripe を呼ぶ」ように見える部分は、Stripe の呼び出しが偽物（4節の `FR-ADMIN-138` を含む）。実 Stripe の証拠ではない。詳しくは[試験仕様](../05_Quality/tests/test-spec.md)の計画3の節。
- 前受金の異常の一覧の理由 `return_refund_retried_during_error`（異常①）は**履歴の印**で、後から消えない。`error` の間にやり直した返金がある注文は、二重に払っていなくても、その後に元の返金が `failed` になっても、一覧に残り続ける。一覧が空にならなくても、残高が0なら対応は要らない（計画2の理由は状態で自然に消える）。`return_waived_with_failed_refund`（異常②）は、`owed`（返すつもりの借り）を支払い済みと数える（借りの一覧と振込で消すので、忘れた0円の終わりではない）。
- 取り消しの区分の `error` の返金は、区分を選ぶ前に「返金のやり直し」が要る場合がある（2節）。
