# 最初の店長を作る手順

> 状態: 現行 | 確認日: 2026-11-17 | 対象: 新しい環境（手元の `db reset` の後・検証用・作り直した本番）の最初の店長。コマンド `npm run admin:bootstrap`

## 概要

新しい環境には店長（`admin` の役割の人）が1人もおらず、店長だけが使える利用者の作成（`/api/admin/create-user`）にも入れない。環境を作る人が、手元の端末でコマンドを1本流して、最初の店長を1人作る。2人目からは店長が管理画面で作る。

| 項目 | 内容 |
| --- | --- |
| いつ使うか | 新しい環境を作った時だけ。普段は使わない |
| 誰が流すか | Supabase の住所と service role キーを持つ人（環境を作る人）。1人で1回だけ流す |
| 何が起きるか | メール確認済みの Auth の利用者が1人でき、`user_roles` に有効な `admin` の役割が付く。監査に `admin_bootstrap` が1行残る |
| TOTP | 作らない。最初のログインで登録する |
| 目指さないこと | 店長が全員ログインできなくなった時の立て直し（パスワード・TOTP の作り直し）は別の話 |

## 前提

- 手元: **本番用。手元は段1a の新しい手順（dev の店員のスクリプト。[Task 10](../superpowers/plans/2026-11-16-passkey-stage1a-foundation.md)）**。段1a の切り替え（Task 9）の後は、このコマンドで作った店長（パスワード＋TOTP）は、手元で `npm run db:reset` の後に動かない（フックが店員のパスワード・メールのコードを拒否する。SEC-AUTH-040）
- ほかの環境: 新しい Supabase に、全部の移行（`supabase/migrations/`）を当てた後。`roles` の表に `admin` の行があること
- 環境変数 `SUPABASE_URL`（無ければ `NEXT_PUBLIC_SUPABASE_URL`）と `SUPABASE_SERVICE_ROLE_KEY` が要る。コマンド自体は `.env` を読まない
- 端末（TTY）から流す。パスワードを字を出さずに聞くため、パイプやリダイレクトでは動かない

## 流し方

手元の Supabase に向ける時（`.env.development.local` を読ませる）:

```powershell
npx tsx --env-file=.env.development.local scripts/admin/bootstrap.ts --email <店長のメール> [--name <表示名>]
```

ほかの環境に向ける時も同じ形にする。リポジトリの外に一時の環境変数ファイルを作り、`SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` の2行だけを書く。キーを端末に打たない（PowerShell の履歴ファイルに平文で残るため）。ファイルはメモ帳などの編集画面で作り、キーを貼り付けて BOM なしの UTF-8 で保存する（`Set-Content`・`Out-File`・`echo ... >` で作ると、キーが履歴に残るうえ、BOM や UTF-16 で `--env-file` が読み損ねる）。同じ端末で前に `$env:SUPABASE_URL` などを置いていたら、そちらが勝つ（`--env-file` は置いてある値を上書きしない）ので、新しい端末で流す。

```powershell
npx tsx --env-file=<リポジトリの外の一時ファイル> scripts/admin/bootstrap.ts --email <店長のメール> [--name <表示名>]
```

流し終えたら、一時ファイルをすぐに消す。

PowerShell か Windows Terminal で流す（Git Bash の標準の端末は TTY にならず、「端末（TTY）から流してください」と出て止まる）。

流すと次の順に進む。

1. 向ける先のホスト名が出る。意図した環境か、必ず目で確かめる（違ったら Ctrl+C で止める）
2. 有効な店長が既にいれば、何もせずに止まる
3. パスワードを2回聞く。会員登録と同じ決まり（16〜128 字・UTF-8 で 72 バイト以内）と、漏洩の照合が掛かる
4. 作れたら、利用者の id とメールが出る

## 止まる場合と次の手

| 出る内容 | 意味 | 次の手 |
| --- | --- | --- |
| 有効な店長がすでにいるため、作りません | その環境には店長がいる | 何もしない。店長の画面から2人目以降を作る |
| このメールアドレスはすでに使われています | 同じメールのアカウントがある | 別のメールにする。そのアカウントを店長にしたい時は、このコマンドでは足りないので相談する。直前に途中で止めた（Ctrl+C など）なら、その Auth の利用者を Supabase の画面で消して流し直す |
| パスワードに制御文字（矢印・Tab・Esc など）が入っています | 入力に操作キーが混ざった | 流し直して、字だけを打つ |
| 取りやめました。何も作っていません | パスワードの入力中に Ctrl+C を押した | 必要なら流し直す |
| 店長の数を確かめられませんでした | 作る前の確認で失敗した（何も作っていない）。住所・鍵・移行の誤りが多い | `SUPABASE_URL`・キー・移行（`roles` の表）を確かめて流し直す |
| パスワードの決まりに合わない・2回の入力が違う | 入力の誤り | 流し直す |
| このパスワードは過去に漏洩しています | 漏洩の照合に掛かった | 別のパスワードにして流し直す |
| 警告: 漏洩パスワードの照合先に届かず、照合せずに作りました | 照合先が使えなかった。作りはした | 監査ログに残っている。最初のログインの後にパスワードを変える |
| 店長の役割を付けられなかったため、作った利用者を消しました | 役割の書き込みが失敗し、後始末は済んだ | 環境の状態（移行・`roles`）を確かめて、流し直す |
| 店長の役割を付けられず、作った利用者も消せませんでした | 利用者が役割なしで残った | 出た id の Auth の利用者を、Supabase の画面で手で消してから流し直す |
| 処理の途中で失敗しました | 想定外の失敗 | 店長が作られていないか、Auth の利用者と `user_roles` を見てから、必要なら流し直す |
| 引数・環境変数・端末の誤り | 使い方の誤り | 出た文に従って直す |

## 注意（守られていないこと）

- 2回を同時に流した時の重なりは防がない。1人で1回だけ流す
- 役割の書き込みは2回の要求（旧い役割を止める・新しい役割を入れる）で、1つの取引ではない。途中で失敗したら、上の表のとおり利用者を消して止まる
- 「作った利用者も消せませんでした」と出たら、その Auth の利用者の id を手で消す（消さないと、同じメールで流し直せない）

## 作った後

作った店長は、そのメールとパスワードでログインする。最初のログインで、メール OTP の後に TOTP の登録の画面（QR コード）が出るので、TOTP を登録する（SEC-AUTH-031）。登録するまで管理画面は使えない。

## 鍵とパスワードの扱い

- service role キーは強い鍵。端末の履歴に残さない（コマンドの行にも `$env:` の行にも書かず、リポジトリの外の一時ファイルを `--env-file` で渡す。使い終わったらそのファイルを消す）
- コマンドは鍵・パスワード・Supabase の誤りの文を出力しない。出力を共有する時も、ホスト名・id・メールだけが出る
- 作ったパスワードは文書・チャットに書かない
