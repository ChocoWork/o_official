# 割引の手順書（プロモーションコード・自動割引）

> 状態: 推定（実装を読んで作成）
> 確認日: 2026-11-01
> 対象: 店長、および割引や注文を管理する担当者

## 概要

管理画面の DISCOUNT で、店の割引を作成・変更・停止し、コードの割り当てと使用状況を確認する手順書です。入金前に注文が終われば使用回数は戻りますが、入金後は返金しても戻りません。遅れた入金で上限を超えた場合は、割引を認めたまま ORDER に要対応を出します。

| 場面 | 見る節 |
| --- | --- |
| 同じコードを何人かに渡す | 2 |
| 1人ずつ別のコードを渡す | 3 |
| 自動の割引を作る・重ね方を確かめる | 4 |
| 使用後の変更・停止・再開・割り当ての解除 | 5〜7 |
| 合計が50円になる・使用回数が戻る条件を知る | 8〜9 |
| 遅れた入金の要対応を確認済みにする | 10 |
| 古い Stripe のコード・失敗したときの対応 | 11〜12 |

実際のコード、配布先の名前、メールアドレスなどの個人情報は、この文書や作業報告に書きません。割り当ては管理画面で確認し、コードを渡すときは、店で決めた個別の連絡方法を使います。作成や割り当てだけで、お客様へのメールが自動送信されることはありません。

## 範囲と根拠

[グループ H の設計](../superpowers/specs/2026-10-28-group-h-promotions-design.md)と[実装計画の Task 12](../superpowers/plans/2026-10-29-group-h-promotions.md)に沿い、現在の画面と処理からまとめています。回数の扱いは[割引の使用の状態](../04_DetailDesign/states/discount-redemptions.md)、支払いの例外を取り消す処理を含む変更の記録は[DB 変更の手順とグループ H の記録](db-migrations.md)を参照してください。

## 1. 管理画面を開く

| 順 | 操作・確認 |
| --- | --- |
| 1 | 管理画面で DISCOUNT を開きます。 |
| 2 | 「状態」「種類」「効き方」で絞るか、「名前・コードで探す」に入力して「探す」を押します。 |
| 3 | 一覧の割引名を押すと詳細が開きます。「割り当て」の表には「コード」「割り当てた人」「状態」「使った日」「注文」が並びます。「注文を見る」で注文の詳細を確認できます。 |

閲覧と操作の権限は別です。「割引を見る権限がありません。」「割引を操作する権限がありません。」と出る場合は、店長に権限の確認を依頼します。ORDER の要対応の確認には、注文を管理する権限が必要です。

## 2. 共有コードを作る

同じコードを複数の人に渡す場合です。割り当てた会員だけに使わせることもできます。

| 順 | 操作 |
| --- | --- |
| 1 | DISCOUNT で「割引を作る」を押します。 |
| 2 | 「割引の名前」「割引の種類」を決め、「効き方」を「コード」にします。割引の名前はお客様にも見えるため、個人名を入れません。 |
| 3 | 「コードの作り方」で「共有コード（1つのコードを使う）」を選び、「コード」に入力します。英数字とハイフンの1〜64字で、大文字・小文字は区別しません。 |
| 4 | 「割引率（％）」または「割引額（円）」、対象の服、「最低条件」を決めます。率は1〜99です。円引きは「最低条件」を「金額」にし、「最低金額（円）」を割引額より大きくします。 |
| 5 | 「使える人」を下の表から選びます。「初回の注文だけ」「全体の回数の上限」「1人1回まで」、期間、重ね方も確認します。回数の上限が空欄なら上限なし、終了が空欄なら期限なしです。日時は日本時間です。 |
| 6 | 「作成する」を押し、開いた詳細で設定を確認します。割り当てが必要なら、下の手順を済ませてからコードを渡します。 |

| 「使える人」の選択 | 使える範囲・追加の操作 |
| --- | --- |
| コードを知っていれば誰でも | 初期設定では会員だけです。ゲストにも許すときだけ「ログインしていない人も使える」にチェックします。割り当ての操作は不要です。 |
| 割り当てた人だけ | 詳細の「割り当てを足す」を押します。「会員を探す」に名前かメールアドレスを2文字以上入れ、該当する会員の「追加」を押し、「割り当てる」を押します。割り当てた会員がログインして使います。 |

共有コードを1人1回にしたい場合は、「1人1回まで」にチェックします。割り当てただけでは1人1回にはなりません。共有コードの割り当ては、同じコードに対して会員ごとに1行ずつ表示されます。

## 3. 1人ずつ別のコードを作る

### 会員に割り当てて作る

| 順 | 操作 |
| --- | --- |
| 1 | 「割引を作る」で名前・種類・値・条件を決め、「効き方」を「コード」、「コードの作り方」を「使い捨てコードの束」にします。 |
| 2 | 「コードの先頭の文字」を入力します。英数字とハイフンの1〜55字で、先頭と末尾は英数字にします。 |
| 3 | 「会員を探す」で対象の会員を探し、それぞれ「追加」を押します。「束の個数」は選んだ人数になります。1回に100人までです。 |
| 4 | 「使える人」を「割り当てた人だけ」にします。ゲストには使えません。期間・回数の条件などを確認し、「作成する」を押します。 |
| 5 | 詳細の「割り当て」の表で、会員ごとに別のコードと「未使用」の行があることを確認し、各人に本人のコードだけを渡します。 |

コードは、先頭の文字にハイフンと4〜8文字の英数字が続く形です。先頭の文字だけでは使えません。各コードは入金後に1回限りとなり、未入金のまま注文が終わった場合は9節のとおり再び使えます。

後から会員を増やす場合は、詳細の「割り当てを足す」で「コードの先頭の文字」を入力し、会員を選んで「割り当てる」を押します。選んだ人数分の新しいコードが作られます。

### 会員を決めずに作る

「使い捨てコードの束」で会員を選ばず、「束の個数」を1〜100で指定し、「使える人」を「コードを知っていれば誰でも」にします。ゲストにも渡すなら「ログインしていない人も使える」を選びます。誰が使えるかを本人に限定するコードが必要なときは、上の会員への割り当てを使います。

## 4. 自動の割引と重ね方

| 項目 | 設定・扱い |
| --- | --- |
| 自動の割引 | 「効き方」を「自動」にします。コードの入力や会員への割り当ては不要で、条件に合う注文に効きます。 |
| リピート割引 | 「A: 前の注文で買った服も数える」はログインした会員の購入履歴を使います。「B: 同じ注文の2着目から」は今回の注文だけを数えます。両方なら通算の2着目以降が対象です。 |
| セット割引 | 「セットにする服（2〜10点、各1着）」を選びます。色・サイズは問いません。そろった組の数だけ割り引きます。 |
| 前もって知らせる | 初期設定ではカートと決済で割引が分かります。商品ページにも案内する場合は「商品の頁で前もって知らせる」を選び、「案内文」を入力します。 |
| 重ね方 | 「商品の割引と重ねる」「注文の割引と重ねる」で選びます。両方の割引が相手との重ね合わせを許す必要があります。同じ1着に効く商品の割引は1つです。 |

次の3点は、設計者が追加した現在の扱いです。オーナーが変更を希望する場合は、実装担当に相談します。

| 項目 | 運用への影響 |
| --- | --- |
| 確認済みの扱い（C20） | 要対応の「確認済みにする」は注意の表示を閉じます。金額・使用履歴・出荷は変えません。 |
| 自動の割引の件数（C21） | 同時に有効にできる自動の割引は合計25件までです。重ねるチェックが1つでも入った自動の割引は、商品の割引と注文の割引でそれぞれ6件までです。作成・期間の変更・再開では、将来の期間の重なりも確認されます。1注文に入力できるコードは5つまでです。 |
| 組み合わせの選び方（C22） | 割引を使うかどうかの組み合わせから選びます。選んだ商品の割引は対象の全着に、セットはほかの商品の割引との比較後にそろう最大の組数に効きます。注文の最低金額を満たすために、セットをわざと1組だけに減らすことはしません。 |

## 5. 使われた後に変えられること

詳細の「編集」から変更し、「保存する」を押します。制限はコード1つごとではなく、割引全体にかかります。入金待ちの使用がある場合も対象で、その後に未入金のまま取り消されて使用回数が戻っても、編集制限は残ります。

| 使用後もできること | 使用後は変えられないこと |
| --- | --- |
| 「割引の名前」「開始（日本時間）」「終了（日本時間）」「全体の回数の上限」の変更 | 「コード」「割引の種類」「効き方」、割引率・割引額、対象の服、「最低条件」の変更 |
| 自動の割引の「商品の頁で前もって知らせる」「案内文」の変更 | 「使える人」「ログインしていない人も使える」「初回の注文だけ」「1人1回まで」、リピートの数え方、重ね方の変更 |
| 「止める」「再開する」、会員への割り当ての追加 | 入金済みの使用履歴や、過去の注文の割引額の書き換え |

値や対象を変えるときは「複製」で新しい割引を作ります。複製は「止めた」の状態で作られ、元のコードと割り当ては引き継ぎません。新しい条件・コード・割り当てを用意し、元の割引を止める必要があるか確認してから、6節の手順で新しい割引を再開します。

## 6. 止める・再開する

| 場面 | 手順と成功の確認 |
| --- | --- |
| 止める | 詳細で「止める」を押します。「止めました。」と表示され、「状態」が「止めた」になったことを確認します。 |
| 再開する | 条件と期間を確認し、「再開する」を押します。「再開しました。」と表示された後の状態を確認します。期間前なら「予定」、期間中なら「有効」、期間が終わっていれば「期限切れ」です。 |
| 再開できない | 自動の割引の件数や、同じ服を含むセット割引の重なりの案内が出たら、ほかの割引の期間・停止状態を見直します。 |

止めても過去の注文の金額と使用回数は変わりません。停止中は新しく割引を使う通常の注文を受け付けませんが、すでに進んだ支払いの遅れた入金を取り消す操作にはなりません。入金後に注意が出た場合は10節で確認します。

## 7. 未使用の割り当てを外す

| 順 | 操作・確認 |
| --- | --- |
| 1 | 詳細の「割り当て」で対象の行を探し、「状態」が「未使用」であることを確認します。 |
| 2 | その行の「外す」を押し、読み直された表から割り当てが外れたことを確認します。 |
| 3 | 共有コードは、その会員への割り当てだけが外れます。1人用の使い捨てコードは、そのコードが使えなくなります。必要なら新しいコードを作って割り当てます。 |

「使用済み（入金待ち）」「使用済み」の行は外せません。操作中に使われて「使用済みの割り当ては外せません。」と出た場合も、最新の状態を確認します。入金前の注文が終了して「未使用」に戻った行は外せます。使用履歴を消すための操作ではありません。

## 8. 合計を50円以上に保つ調整

割引を重ねて支払額が50円未満になる場合は、まず注文の割引を少なくして合計を50円にします。注文の割引を削るだけで足りない場合や、注文の割引がない場合は、商品の割引も少なくします。0円の注文にはしません。

| 計算例 | 調整前 | 調整後 |
| --- | --- | --- |
| 商品の合計 | 1,000円 | 1,000円 |
| 商品の割引 | 100円 | 100円 |
| 注文の割引 | 880円 | 850円 |
| 支払額 | 20円 | 50円 |

この例では注文の割引を30円減らしています。設定した率や額より実際の割引が小さくなることがあります。お客様には、確認画面と注文に表示された割引の内訳と合計を案内します。

## 9. 使用回数と割り当ての状態

一覧の「使った回数」は、入金待ちの予約と入金済みの確定を合わせた数です。コードを入力して見込みを確認しただけでは回数を使いません。注文の受付で予約し、入金を確認すると確定します。

| 注文・操作の状態 | 回数・割り当てへの影響 |
| --- | --- |
| 入金待ち | 回数に含み、割り当ては「使用済み（入金待ち）」です。支払いが続いている間は予約を保ちます。 |
| 入金なしで放棄・期限切れ・決済失敗・取消になり、注文が終了 | 予約を取り消して使用回数を戻します。割り当ては「未使用」に戻り、全体の回数・1人1回・使い捨てコードの使用枠を再び使えます。初回の注文だけの予約も戻ります。 |
| 支払いの例外を「注文を取り消して解決」 | 未入金の注文を取り消した場合は、同じく回数を戻します。取消を伴わない解決では予約を保ちます。 |
| 入金を確認 | 「使用済み」となります。その後はキャンセル・返品・一部返金・全額返金でも回数を戻しません。初回の資格も戻りません。 |
| 未入金で終了した後に遅れて入金 | 使用を確定し直します。上限などを超えていても割引を認め、要対応を出します。 |

決済画面を閉じた直後や、決済を1回試して失敗しただけでは、注文の終了処理がまだ済んでいない場合があります。回数が戻らないときは「注文を見る」で注文の状態を確認し、入金済みの使用を手作業で戻そうとしないでください。

## 10. 遅れた入金の要対応を確認する

未入金で終了した後の入金や、通常の受付を通らず回復した入金では、回数・1人1回などの条件を超えることがあります。入金した注文の割引は認めて確定し、店長が確認できるよう注意を出します。この注意だけで注文や発送を止めることはありません。

| 表示場所・文 | 意味 |
| --- | --- |
| ORDER の要対応欄の「割引」に「割引の上限を超えた注文」 | 全体の回数・1人1回・使い捨てコードの回数のいずれかを超えて確定した注文です。 |
| 同じ欄に「割引の条件を確認する注文」 | 遅れた入金などを回復して確定した注文です。回数の超過がなくても出る場合があります。 |

| 順 | 手順・成功の確認 |
| --- | --- |
| 1 | 管理画面の ORDER を開き、注文一覧の上の要対応欄の「割引」を確認します。 |
| 2 | 注文へのリンクを開き、入金の状況と「割引」の内訳を確認します。今後も同じ割引を使わせるかを判断し、必要なら DISCOUNT の詳細で「止める」を押します。 |
| 3 | ORDER の要対応欄に戻り、対象の注文の「確認済みにする」を押します。対象の注意が一覧から消えたことを確認します。ほかにも要対応がある旨の表示があれば、続けて確認します。 |

「確認済みにする」は注意の表示だけを閉じます。注文金額、割引額、使用回数、使用履歴、出荷は変わりません。返金や回数を戻す操作ではありません。

## 11. 古い Stripe のプロモーションコード

| 項目 | 扱い |
| --- | --- |
| お店のコード入力欄 | DISCOUNT で作った店のコードを使います。Stripe の管理画面で作った古いプロモーションコードは受け付けません。 |
| 2026-11-01 時点の記録 | 接続されている Stripe のサンドボックスでは、有効な旧プロモーションコードは0件です。本番側の件数を確認したという意味ではありません。 |
| 今後の作成・配布 | 店の割引は DISCOUNT で作成します。旧コードについて問い合わせが来たら、対象の条件を確認し、必要に応じて店のコードを用意します。 |

## 12. 失敗したときの再試行と停止

| 表示・場面 | 対応 |
| --- | --- |
| 「割引を読み込めませんでした。」などの読込失敗 | 「読み直す」を押します。読めないだけで停止したと判断せず、復旧後に状態を確認します。 |
| 「保存できませんでした。」「操作に失敗しました。」など、結果が分からない | 画面に表示中の内容を保ち、一覧や詳細で反映済みかを確認します。未反映なら同じ内容で再試行します。同じ割引を新しく作り直す前に、重複していないかを確認します。 |
| 「変更しましたが、最新の情報を読み込めませんでした。」 | 変更は済んでいます。「読み直す」で最新の状態が見えるまで待ち、同じ変更を重ねません。 |
| 「設定が変わりました。読み直してください。」 | 最新の詳細を開き直し、ほかの担当者の変更を確認してから、必要な操作だけを行います。 |
| 「このコードは既に使われています。」 | 別のコード、または別の「コードの先頭の文字」に変えます。この文は文字の重複を表し、入金済みの意味とは限りません。 |
| 「入力を確かめてください。」や欄ごとの案内 | 指摘された欄を直します。使用後の編集制限や、使用済みの割り当ての解除は再試行しても通りません。 |
| 「しばらくしてから、もう一度お試しください。」 | 連続して押さず、時間をおいて再試行します。認証が必要と出た場合は再ログインします。 |
| お客様がコードの確認や決済を進められない | 入金や注文がすでに成立していないか ORDER で確認します。未成立なら、時間をおいて入力画面から割引と合計を確かめ直してもらいます。 |
| DISCOUNT に「割引の計算を確認してください。」 | 割引名を押して詳細を開き、条件と重ね方を実装担当に確認してもらいます。確認後、詳細の「確認済みにする」で注意の表示を閉じます。ORDER の入金の要対応とは別です。 |
| 意図しない割引が続く・計算の注意が繰り返す | 対象の詳細で「止める」を押し、「止めた」を確認して、新しい利用を止めます。既存注文の入金・金額・発送は別に確認します。原因と設定を確認できてから6節の手順で再開します。 |

停止自体が失敗した場合は、止まったと案内せず、読み直して状態を確認し、実装担当へ連絡します。担当者と連絡先の保管場所は、店長と実装担当の間で決めておきます。調査の記録は、日時・操作名・画面の固定の案内文・件数・確認結果にとどめ、コードやお客様の個人情報を転記しません。
