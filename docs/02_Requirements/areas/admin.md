### DRV-ADMIN-006 管理の返信は保存を先にし、メールが送れなくても保存を残す

| 属性 | 値 |
| --- | --- |
| 根拠 | 店の答えの記録（スレッド）を失わないため、メールの失敗で保存を取り消さない。送れなかったことは応答の印と監査の結果で知らせる。FREQ-25-AC-01 は「メール送信されスレッドに反映」だけを決め、片方が失敗した時の扱いを決めていない。理由の記録は無い（推定） |
| 状態 | 推定 |
| 出どころ | 実装から推定（`src/app/api/admin/contact/[id]/reply/route.ts`）。`docs/03_BasicDesign/api/api-spec.md` |

`POST /api/admin/contact/[id]/reply` は次の順で動く。

1. 問い合わせが無ければ 404
2. 店の返信（送り手は店、経路は web）をやり取りに保存する。失敗すれば 500
3. 問い合わせの状態を answered にし、最後のやり取りの時刻を更新する（失敗は見ない）
4. 送り手の住所の設定（`MAIL_FROM_ADDRESS`）があれば、お客様のメールへ送る。件名は元の件名の頭に `Re:` を付ける（既に付いていれば付けない）。本文の後に店の名前を添える。返信のアドレスの設定があれば、スレッドごとの返信のアドレスを Reply-To に入れる
5. 監査に結果を残し、201 と `mailSent`（送れたか）を返す

メールが送れなければ `mailSent` は偽、監査は reply_saved_mail_failed。送り手の住所の設定が無い時は、メールを送らないのに `mailSent` は真、監査は reply_sent になる（TM-ADMIN-07）。
